# KR52.5 — Памʼять дослідженого й тон сцени

**Ціль:** [O52](README.md) · **Стан:** ⚪ лише за запитом власника чи майстрів · **Залежить від:** [KR52.3](kr52.3-light-vision.md)

Дві незалежні частини; кожну можна взяти окремо. План тут менш детальний, ніж в інших KR:
перед реалізацією уточнити за відгуком після KR52.3.

## А. Тон сцени (дешево)

Ідея Кима: «атмосферне освітлення — світанкове чи нічне».

- `ALTER TABLE game_scene ADD COLUMN tone varchar(6) NOT NULL DEFAULT 'none' CHECK (tone IN ('none','dawn','dusk','night','cave'))`.
- Один `<div>` над картинкою мапи й обʼєктами, під токенами: суцільний колір з
  `mix-blend-mode: multiply`. Без анімації, без впливу на видимість і правила.
- Вибір — у панелі «Світло» або «Вигляд» майстра; гравці бачать той самий тон.
- Перевірити на iOS WebKit, що `mix-blend-mode` над великою картинкою не гальмує зум; якщо так —
  звичайна напівпрозора заливка без змішування.

## Б. Памʼять дослідженого

Місця, де герої вже були, лишаються видимими тьмяно, без токенів (Explorer Mode у Roll20).
Це найдорожча частина динамічного освітлення в конкурентів, тож не робимо без запиту.

Ескіз:

- Памʼять — растр низької роздільності (до 256 px по довгій стороні) на сцену й пристрій; після
  кожного відпускання токена в нього домальовується поточна видима область (2D-canvas поза екраном).
- Зберігання локальне (IndexedDB, ключ — сцена й користувач): узгоджено з Р63 «туман клієнтський».
  Наслідок: на іншому пристрої памʼять порожня. Спільна памʼять партії на сервері — окреме рішення.
- У масці темряви растр іде `<image>` сірим кольором під динамічними просвітами.
- «Забути досліджене» — дія майстра: лічильник `explored_epoch` у `game_scene`, клієнт скидає растр,
  коли число змінилось. Нова мапа сцени теж збільшує лічильник.
- Токени в дослідженій, але зараз невидимій зоні сховані.
