# KR52.3 — Освітлення, зір і темрява

**Ціль:** [O52](README.md) · **Стан:** ⚪ не розпочато · **Залежить від:** [KR52.1](kr52.1-visibility-geometry.md), [KR52.2](kr52.2-walls-doors.md)

## Мета

Майстер вмикає освітлення сцени — і гравці бачать лише те, що бачать їхні герої. Темрява
відступає під пальцем, коли гравець тягне свій токен. Істота в темряві не показана.

## Схема

`db/changes/<дата>-game-scene-lighting.sql`, лише додавання зі сталими типовими значеннями:

```sql
ALTER TABLE public.game_scene
  ADD COLUMN lighting varchar(6) NOT NULL DEFAULT 'off'
    CONSTRAINT game_scene_lighting_check CHECK (lighting IN ('off', 'bright', 'dim', 'dark'));

CREATE TABLE public.game_scene_light (
  game_scene_light_id serial PRIMARY KEY,
  game_scene_id integer NOT NULL REFERENCES public.game_scene(game_scene_id) ON DELETE CASCADE,
  x real NOT NULL CHECK (x BETWEEN 0 AND 1),
  y real NOT NULL CHECK (y BETWEEN 0 AND 1),
  bright_feet smallint NOT NULL CHECK (bright_feet BETWEEN 0 AND 300),
  dim_feet smallint NOT NULL CHECK (dim_feet BETWEEN 0 AND 300),
  is_on boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX game_scene_light_scene_idx ON public.game_scene_light (game_scene_id);

-- Світло, яке несе токен, і ручна поправка темного зору героя (null — з листа).
ALTER TABLE public.game_scene_hero_token
  ADD COLUMN light_bright_feet smallint NOT NULL DEFAULT 0,
  ADD COLUMN light_dim_feet smallint NOT NULL DEFAULT 0,
  ADD COLUMN darkvision_feet smallint;
ALTER TABLE public.game_map_creature
  ADD COLUMN light_bright_feet smallint NOT NULL DEFAULT 0,
  ADD COLUMN light_dim_feet smallint NOT NULL DEFAULT 0;
```

`dim_feet` — «ще стільки-то тьмяного» понад яскраве, як у книзі: смолоскип 20 + 20.
Нагадування з памʼяті проєкту: колонку, яку вже читає задеплоєний код, не можна прибирати до
релізу без неї — тут лише додавання, тож порядок простий: SQL, потім код.

## Правила — `src/rules/game-lighting.ts`

```ts
export type SceneLighting = "off" | "bright" | "dim" | "dark";
export type LightSource = { at: TokenPosition; brightFeet: number; dimFeet: number };
export type Eye = { at: TokenPosition; darkvisionFeet: number };
export type SightInput = { lighting: SceneLighting; segments: SightSegment[]; lights: LightSource[]; eyes: Eye[]; frame: MapFrame | null; aspect: number };

// Усе, що потрібно шару: многокутники очей і світла вже пораховані.
export function buildSceneSight(input: SightInput): SceneSight;
// "bright" | "dim" | "hidden" — для токенів.
export function findPointSight(point: TokenPosition, sight: SceneSight): PointSight;
export const LIGHT_PRESETS: Array<{ key: string; brightFeet: number; dimFeet: number }>;
```

Правило видимості точки — у таблиці «Модель» [README](README.md#модель). Рівень: `bright`, якщо
точка в яскравому радіусі джерела або сцена `bright`, або сцена `dim` і точка в радіусі темного
зору; `dim` — тьмяний радіус, сцена `dim`, або темрява в радіусі темного зору; інакше `hidden`.

Готові джерела (числа з PHB; українські назви й ключі — через скіл `dnd-ua-translation` перед
комітом): свічка 5/5, смолоскип 20/20, ліхтар із заслінкою 30/30, ліхтар спрямований 60/60 (як
коло — спрощення), заклинання «Світло» 20/20, «Денне світло» 60/60, «Танцюючі вогники» 0/10.

Збирання очей і світла — `src/rules/` приймає готові числа; хто є оком, вирішує сервер у вигляді:

- `GameSessionView` отримує `lighting`, `lights` (сцена), а в героїв і істот на мапі —
  `light: { brightFeet, dimFeet } | null`; у героїв ще `darkvisionFeet`.
- Темний зір героя: `darkvision_feet ?? calculateDarkvisionRange(pers)`
  ([bonus-calculator.ts](../../src/lib/logic/bonus-calculator.ts)). Перед реалізацією перевірити,
  скільки коштує цей розрахунок у запиті вигляду кімнати: якщо він тягне весь `PersWithRelations`,
  рахувати один раз при привʼязці героя або ставленні токена й зберігати в `darkvision_feet`.
- Очі гравця — усі герої на сцені (Р69). Істоти очима
  не є, навіть союзники: майстер бачить усе й так.

## Малювання

Розширюємо `MapFogLayer` у [MapOverlay.tsx](../../src/components/games/MapOverlay.tsx), другого шару
не додаємо. У масці (білий — темрява лишається):

1. Наявний вміст ручного туману.
2. Якщо освітлення не `off`: група, обрізана `clipPath` з многокутників усіх очей; усередині —
   - для `bright`/`dim`: прямокутник на всю мапу (чорний для `bright`, сірий для `dim`);
   - для кожного джерела: його многокутник видимості із заливкою `radialGradient` з центром у
     джерелі — чорний до яскравого радіуса, сірий до тьмяного, прозорий на краю;
   - для кожного ока з темним зором: коло радіуса зору (сіре в `dark`, чорне в `dim`).
3. Ручний туман накладається останнім — сховане рукою лишається схованим. Для цього порядок у
   масці: спершу «все біле», потім динамічні просвіти, потім білі фігури ручного туману.

Мʼякий край дає градієнт; наявний фільтр `feMorphology + feGaussianBlur` лишається лише на
ручному тумані, як зараз. Тіні від стін у першій версії різкі.

Майстер: та сама вуаль, що й для туману (`isVeil`), плюс кола джерел світла тонким контуром;
«Як бачать гравці» — наявний перемикач `isFogPreview`, поширений на освітлення.

Токени: `layout.isHidden` у [MapBoard.tsx](../../src/components/games/MapBoard.tsx) додає умову
`findPointSight(position, sight) === "hidden"`. Герої не ховаються ніколи. Велику істоту
перевіряємо за центром і чотирма кутами її квадрата — видно, якщо видно хоч одну точку.

Живий рух: поки гравець тягне свого героя, око цього героя стоїть у `drag.to` (вже є в MapBoard
як `move`). Перерахунок — не частіше одного разу на кадр (`requestAnimationFrame`), `buildSceneSight`
мемоїзується за стінами, світлом і позиціями. Інші учасники бачать нову картину після відпускання.

Плавний перехід (рішення власника, Р69): коли картину змінив не власний палець — прийшов знімок
кімнати з чужим рухом, дверима чи світлом, — попередній шар темряви лишається зверху й гасне за
180 мс (`opacity`, CSS-перехід), нова картина під ним уже готова. Істоти, що стали видимими,
проявляються за той самий час, починаючи з `opacity: 0.01`, а не з 0: iOS ковтає дотики по
елементу, що проявляється з нуля. З `prefers-reduced-motion: reduce` — миттєво. Під власним
пальцем переходу немає: там темрява й так рухається щокадру.

### Стіни зупиняють токени гравців

Рішення власника (Р69): «як у конкурентів» — [порівняння](questions.md#як-стіни-зупиняють-рух-у-конкурентів).

- Лише сцени з `lighting !== 'off'`, лише коли тягне гравець. Майстер не обмежений.
- `findAllowedMove(from, to, segments)` у `src/rules/map-visibility.ts`: якщо відрізок від останньої
  дозволеної точки «примари» до нової точки пальця перетинає стіну чи зачинені двері — «примара»
  лишається на місці. Перевірка на кожен рух пальця, а не від початку перетягування, тож обійти
  кут можна. Око під час перетягування стоїть у дозволеній точці.
- Відпускання ставить токен у останню дозволену точку. Сервер шлях не перевіряє: це та сама
  довіра, що й у Р63.
- Гравець бачить причину: «примара» зупинилась біля стіни, під нею коротке «Стіна». Без цього
  зупинка на телефоні виглядає як поломка.
- Тести: крізь стіну — ні; крізь відчинені двері — так; довкола кута — так; майстер — завжди.

Код шару й правил освітлення підвантажується динамічним імпортом лише коли `lighting !== "off"`.

## Панель «Світло» (майстер)

Новий інструмент `"light"`:

- перемикач освітлення сцени: Вимкнено / Світло / Сутінки / Темрява, з поясненням одним рядком;
- «Додати джерело» — вибір із готових або свої числа; джерело ставиться в центр екрана й тягнеться
  ручкою `MapHandle`; дотик по джерелу — змінити, вимкнути, видалити;
- без сітки: джерела вимкнені з підказкою «Спершу підженіть сітку — світло міряється футами».

Світло на токені — рядок «Світло» в наявній панелі вибраного токена
([TokenTransformControls.tsx](../../src/components/games/TokenTransformControls.tsx)): гравець — своєму
герою, майстер — будь-кому. Там само майстер бачить і може перебити темний зір героя.

Стани для гравця: героя немає на сцені, а сцена темна — на мапі напис «Поставте героя на мапу,
щоб бачити»; сцена `dark` без жодного світла й без темного зору — видно лише власну клітинку
(око завжди бачить радіус 5 фт, щоб не загубити токен).

## База й дії

`src/server/db/game-scene-lighting.ts`: `setSceneLighting`, `saveSceneLight`, `removeSceneLights`
(майстер); `setTokenLight` для героя (власник або майстер) і істоти (майстер). Зняття токена з
мапи світло не скидає — смолоскип лишається в руці. Нова мапа сцени видаляє джерела сцени й
повертає `lighting = 'off'`.

## Тести

- `tests/rules/game-lighting.test.ts`: чотири режими; світло за стіною не освітлює; темний зір у
  темряві дає `dim`; істота за зачиненими дверима `hidden`, за відчиненими — видима; велика істота
  видна за краєм.
- `tests/db/game-map.test.ts`: права на зміну освітлення й світла токена; нова мапа скидає.
- `tests/components/game-room-map.test.tsx`: гравцю не малюється істота в темряві; майстру — малюється.
- Браузер на копії, 375 WebKit і 1280 Chromium: підземелля з трьома кімнатами, гравець тягне героя
  крізь двері — істота зʼявляється, коли на неї падає світло.

## Приймання

Сценарій Кима: гравець рухає токен, темрява відступає, з темряви «визирає монстр». Плюс ворота
швидкості з [KR52.6](kr52.6-phone-acceptance.md). Сцени з `lighting = 'off'` поводяться рівно як до KR.

## Поза KR

Кольорове світло, конуси, мерехтіння, памʼять дослідженого ([KR52.5](kr52.5-explored-atmosphere.md)),
сліпий зір і справжній зір, магічна темрява, індивідуальний зір кожного гравця.
