# KR52.1 — Геометрія видимості

**Ціль:** [O52](README.md) · **Стан:** ✅ готово · **Залежить від:** —

## Мета

Чисті функції, які відповідають на два питання: «яку частину мапи видно з цієї точки» і «чи видно
цю точку». Без React, без бази — їх однаково викликають шар темряви, приховування токенів і тести.

## Що робимо

Новий файл `src/rules/map-visibility.ts` (усе в координатах шару: `toViewPoint` з
[game-grid.ts](../../src/rules/game-grid.ts), ширина мапи 100).

```ts
export type ViewPoint = { x: number; y: number };
export type SightSegment = { from: ViewPoint; to: ViewPoint };

// Многокутник того, що видно з origin. radius обрізає пошук: стіни далі за нього не беруться,
// а межею стає квадрат зі стороною 2·radius (коло домальовує шар градієнтом).
export function buildVisibilityPolygon(origin: ViewPoint, segments: SightSegment[], radius: number): ViewPoint[];

export function isPointInPolygon(point: ViewPoint, polygon: ViewPoint[]): boolean;

// Футів у одиницю шару: клітинка = 5 фт = 100 / columns.
export function findFeetAsViewUnits(feet: number, gridColumns: number): number;
```

Алгоритм `buildVisibilityPolygon`:

1. Залишити відрізки, що зачіпають квадрат радіуса, додати чотири сторони цього квадрата.
2. Для кожного кінця відрізка — три кути: на точку й ±0,0001 рад.
3. Для кожного кута — найближчий перетин променя з відрізками.
4. Відсортувати точки за кутом.

Це O(n²); у коді лишити `// shortcut: O(n²), до ~400 відрізків; далі — обхід за кутом (Red Blob)`.

Крайні випадки, які мають бути в тестах:

- око всередині зачиненої кімнати — многокутник дорівнює кімнаті;
- колона посеред кімнати — за нею тінь, обабіч видно;
- щілина дверей — видно конус за дверима;
- око точно на стіні або в її кінці — зсунути око на 0,001 до центру клітинки, не ділити на нуль;
- два відрізки зі спільним кінцем (кут кімнати) — промінь не протікає крізь кут;
- стін немає — повертається квадрат радіуса.

## Тести

`tests/rules/map-visibility.test.ts` — випадки вище через `isPointInPolygon` для контрольних
точок («за стіною — ні, у дверях — так»), а не через порівняння масивів вершин. Тест на час
не пишемо (нестабільний); замір — окремий скрипт у scratchpad, числа — в журнал.

## Приймання

- `bun run test:no-db` зелений, гейт покриття правил проходить.
- Замір на ноутбуці: 400 відрізків, радіус на всю мапу — ≤ 15 мс; радіус 60 фт на мапі 40
  клітинок — ≤ 3 мс. Якщо гірше — одразу обхід за кутом, не чекаючи телефона.

## Поза KR

Обʼєднання многокутників, мʼякі тіні, односторонні стіни.

## Журнал

- 2026-11-10 — план. Прототип у scratchpad сесії показав 3 мс на 300 відрізків і ~19 мс на 500
  (уся мапа, без відсікання).
- 2026-11-11 — код: `src/rules/map-visibility.ts` (`buildVisibilityPolygon`, `isPointInPolygon`),
  10 тестів у `tests/rules/map-visibility.test.ts`. Відхилення: `findFeetAsViewUnits` не додано —
  радіус у футах уже дає `findViewUnitsPerFoot(frame)` з `game-grid.ts`. Стіни, що перетинають межу
  квадрата радіуса, обрізаються по ній (Liang–Barsky): інакше точка перетину не стає вершиною і
  многокутник зрізає кут. Око на стіні зсувається на 0,001 по діагоналі в перший бік, де стіни немає
  (центру клітинки функція не знає; токени стоять у центрах клітинок, тож це рідкісний випадок).
  Замір (bun, ноутбук, 400 випадкових відрізків, 200 прогонів): уся мапа — **4,1 мс**, радіус 60 фт
  на мапі 40 клітинок — **0,8 мс**. Обхід за кутом не потрібен.
- 2026-11-11 — ворота KR52.6 на еталонній сцені (308 відрізків, кімнати) не пройшли: око гравця
  дивиться на всю мапу, і в Chromium з 4× уповільненням перерахунок брав p75 18 мс. Замість обходу
  за кутом — точне прискорення: стіни сортуються за відстанню від ока, промінь зупиняється, щойно
  наступна стіна далі за знайдену точку. Многокутники ті самі (контрольна сума збіглася), повний
  перерахунок сцени без кешу в bun — 13 → 2,5 мс. На відкритій мапі з розкиданими стінами найгірший випадок
  лишається O(n²) (`shortcut:` у коді). Тест «довга стіна з далекими кінцями» ловить хибне сортування.
