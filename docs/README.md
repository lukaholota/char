# Документація char.holota.family

Точка входу для роботи над українським конструктором і листом персонажа, каталогами та
довідником D&D. Платформа підтримує **2014 і 2024 в одному коді**. Якщо редакцію не задано,
використовуємо 2014; правило чи контент завжди звіряємо з джерелом своєї редакції.

## Як почати задачу

Запит власника визначає поточну роботу. Знайди відповідну ціль у
[каталозі цілей](OBJECTIVES.md), прочитай її KR і останній журнал або handoff.
Для локальної правки поза цілями достатньо повʼязаного коду та правил роботи.
Старі черги «що робити зараз» не є дорученням відновлювати завершені задачі.

| Що потрібно | Де читати |
|---|---|
| Стек, карта коду, постійні правила роботи | [CLAUDE.md](../CLAUDE.md); для Codex також [AGENTS.md](../AGENTS.md) |
| Знайти ціль або попередню реалізацію | [OBJECTIVES.md](OBJECTIVES.md) → README цілі → конкретний KR і журнал |

## Статус

Фундамент тестів, фіксації поведінки, відокремлення правил і підтримки 2024 вже реалізований
([O1](o1-safety-net/README.md), [O2](o2-characterization/README.md),
[O3](o3-rules-engine/README.md), [O4](o4-ui-decomposition/README.md),
[O5](o5-rules-2024/README.md)). Старий порядок «спершу сітка безпеки, потім 2024» пояснював
початок робіт; він більше не блокує задачі 2024. Це не означає, що всі наступні KR закриті
чи що будь-яка механіка вже покрита тестом.

Поточні залишки, приймання й backlog записуються **у відповідній цілі**, без другої таблиці
прогресу тут. Свіжі напрями для навігації, а не призначена черга:

| Напрям | Документи |
|---|---|
| Якість конструктора, листа й підвищення рівня | [O31](o31-builder-release-quality/README.md) |
| Термінологія й лор каталогів | [O32](o32-corpus-terms/README.md), [O33](o33-catalog-prose/README.md) |
| Підкласи зі старих книг у 2024 | [O43](o43-legacy-subclasses-2024/README.md) |
| Читання каталогів | [O44](o44-catalog-reading/README.md) |
| Вага JS і швидкість сторінок | [O46](o46-js-weight/README.md) |
| Хоумбрю у Диких формах | [O47](o47-homebrew-wildshape/README.md) |
| Автоматична видача заклинань 2014 і залишок виборів | [O48](o48-granted-spells-2014/README.md) |

**«Реалізовано», «засіяно», «закомічено» й «задеплоєно» — окремі факти.** Для кожного
важливі дата й доказ: тест, результат сіду, коміт або успішний деплой. Старий вимір у STATE
не підтверджує стан сьогодні. За розбіжності перевіряй потрібний код чи середовище;
дані бази самі по собі не доводять правильність правила D&D.

## Як вести ці документи

- У KR зверху тримай поточний статус і дату, нижче — критерії та журнал. При завершенні
  синхронізуй статус KR і його рядок у README цілі; не лишай «заплановано» над виконаною таблицею.
- У журналі записуй результат, перевірку, межі перевіреного й те, що залишилося.
  Посилайся на коміт, SQL, джерело чи артефакт, якщо це допоможе наступній сесії.
- У [STATE.md](STATE.md) додавай датований вимір із методом і середовищем; зберігай попередні
  зрізи як історію. Не змінюй дату старих чисел на сьогоднішню без нового виміру.
- Нове рішення власника записуй у [DECISIONS.md](DECISIONS.md). Якщо воно замінило старе,
  познач це й дай посилання. Знахідки аудиту зберігай у документах, а не лише в чаті чи `/tmp`.
- Цей файл — навігація. Не додавай сюди щоденні логи, кількість тестів, рядків бази чи копії
  статусів усіх KR. Нову ціль додавай до [OBJECTIVES.md](OBJECTIVES.md).

Його черга й статуси історичні; читати його на початку кожної сесії не потрібно.
