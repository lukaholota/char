# Стратегія розвитку char.holota.family

Точка входу. Кожна сесія Claude читає це разом із [CLAUDE.md](../CLAUDE.md).

## Головна теза

Проблема проєкту — не архітектура. Проблема в тому, що **поведінка платформи ніде не зафіксована**.
90% коду написав ШІ за промптами, рядково його ніхто не перевіряв, єдиний спосіб дізнатися, що
продукт робить — відкрити браузер і створити персонажа руками. Через це рефакторити страшно, баги
знаходять користувачі, а кожна нова сесія має шанс зламати те, що працювало.

Послідовність жорстка:

> **сітка безпеки → зафіксувати поведінку → рефакторити → правила 2024**

Не починати O2 до закриття O1. Не починати O3 до закриття O2. Не чіпати 2024 до закриття O3.

## Як вести ці документи

Кожен KR — окремий файл із блоком статусу зверху і журналом знизу. Коли працюєш над KR:
став статус `🔄 в роботі`, відмічай чекбокси в «Готово, коли», дописуй у «Журнал» те, що
з'ясувалося по дорозі — особливо неприємні сюрпризи. Журнал важливіший за чекбокси: саме він
рятує наступну сесію від повторного відкриття тих самих граблів.

Прогрес у таблиці вище оновлювати руками при закритті KR.

Плани O4 і O5 навмисно залишені начерками. Детальний план роботи, до якої дійдеш через
півроку, — це вигадка; він писатиметься, коли попередня ціль закриється і стане видно реальний стан.
