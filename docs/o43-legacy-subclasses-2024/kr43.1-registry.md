# KR43.1 — Реєстр легасі-підкласів і правило зсуву рівнів

**Ціль:** [O43](README.md) · **Статус:** ✅ зроблено 2026-09-25 · **Залежить від:** — · **База:** не потрібна (CI-безпечно, [Р32](../DECISIONS.md#р32))

## Навіщо

Одне місце, яке каже «цей підклас 2014 доступний персонажу 2024, ось звідки він і ось як його
заклинання звуться у 2024». Його читають сід (KR43.2), генератори (KR43.3), майстер (KR43.4) і
вибір заклинань (KR43.5). Без реєстру кожен із них вирішував би сам — рівно той клас помилок
«працює на 50 екранах, ламається на 51-му».

## Кроки

### 1. Файл `data/2024/legacy-subclasses.json`

```json
{
  "note": "O43. Підкласи зі старих книг, доступні класам 2024. Лише підкласи без перевидання у 2024 і без назви, зайнятої під класом 2024. Рівні не тут: правило зсуву одне — src/rules/legacy-subclasses-2024.ts.",
  "subclasses": [
    { "class2014": "WARLOCK_2014", "class2024": "WARLOCK_2024", "subclass": "THE_GENIE",  "source": "TCOE" },
    { "class2014": "WARLOCK_2014", "class2024": "WARLOCK_2024", "subclass": "HEXBLADE",   "source": "XGTE" },
    { "class2014": "WARLOCK_2014", "class2024": "WARLOCK_2024", "subclass": "FATHOMLESS", "source": "TCOE" },
    { "class2014": "WARLOCK_2014", "class2024": "WARLOCK_2024", "subclass": "UNDYING",    "source": "SCAG" }
  ],
  "spellRenames2014To2024": { "Branding Smite": "Shining Smite" }
}
```

- `source` — значення enum `Source` (`prisma/schema.prisma:2054-2108`), бо його читають
  `sourceTranslations` (`src/lib/refs/translation.ts:996`) і `SourceBadge`. TCoE — `TCOE`, XGtE —
  `XGTE`, SCAG — `SCAG`.
- Списки заклинань **не дублюються**: вони вже лежать у `data/2014/warlock-expanded-spell-lists.json`
  (генерований з 5etools, з `genieKind`). Реєстр додає лише перейменування.
- `spellRenames2014To2024` — лише ті назви, що трапляються в списках підкласів реєстру. Зараз одна:
  Branding Smite (Hexblade, 2-й рівень).

### 2. Правило `src/rules/legacy-subclasses-2024.ts`

Чисте, без Prisma. Імпорт JSON маленький (≈1 КБ), тож модуль безпечний і для клієнта, але клієнт
його не потребує: позначку легасі приносить згенерований контент (KR43.3).

```ts
import registry from "../../data/2024/legacy-subclasses.json";

export type LegacySubclass2024 = { class2014: string; class2024: string; subclass: string; source: string };

export const LEGACY_SUBCLASSES_2024: readonly LegacySubclass2024[] = registry.subclasses;

export function findLegacySubclass2024(class2024: string, subclass: string): LegacySubclass2024 | null
export function isLegacySubclass2024(class2024: string, subclass: string): boolean
export function shiftLegacyLevel(levelIn2014: number, subclassLevel2024: number): number   // Math.max
export function shiftLegacyLevels(levels: readonly number[], subclassLevel2024: number): number[] // зсув + dedupe + sort
export function findSpellEngName2024(engName2014: string): string                          // rename або та сама назва
```

Коментар над `shiftLegacyLevel` — один рядок із джерелом правила (5etools XPHB-копії, О43), бо це
неочевидно з коду. Решта — без коментарів.

### 3. Юніт-тест `src/rules/legacy-subclasses-2024.test.ts`

| Кейс | Очікування |
|---|---|
| `shiftLegacyLevel(1, 3)` / `(2, 3)` / `(6, 3)` / `(3, 3)` | 3 / 3 / 6 / 3 |
| `shiftLegacyLevels([1, 1, 6, 10, 14], 3)` | `[3, 6, 10, 14]` |

Червоний: замінити `Math.max` на повернення аргументу — падає перший рядок.

### 4. Гейт реєстру `tests/content/legacy-subclasses-2024-registry.test.ts`

Без бази; у `vitest.config.mts` (юніт). Читає лише закомічені файли.

1. **Кожен підклас реєстру існує як підклас 2014 свого класу** — у
   `prisma/seed/subclassSeed.ts` (`SUBCLASS_SEED_INPUTS`, `classConnect === class2014`), бо
   `creator-content-*.json` не комітяться ([Р13](../DECISIONS.md#р13)).
2. **Жоден не зайнятий під класом 2024**: немає запису в `data/2024/normalized/subclasses.json`
   з тим самим класом, чий `toSubclassEnum(engName)` дорівнює назві. Інакше сід упреться в
   `@@unique([classId, name])`.
3. **Жоден не перевиданий**: для 5etools-запису з `classSource: "PHB"` і тим самим `shortName`
   у `data/5etools/raw/class/class-<клас>.json` поле `reprintedAs` відсутнє. Мапу `subclass enum →
   shortName` покласти в тест явно (`THE_GENIE → "Genie"`, `HEXBLADE → "Hexblade"`, `FATHOMLESS →
   "Fathomless"`, `UNDYING → "Undying"`) — вгадування за підрядком уже дало одну хибу при вимірі
   («Light» знайшлося в «Twilight»).
4. **`source` — значення enum `Source`** і має переклад у `sourceTranslations`.
5. **Кожне заклинання списку підкласу має рядок 2024**: для кожного `engName` з
   `warlock-expanded-spell-lists.json` (лише підкласи реєстру) `findSpellEngName2024(engName)` є в
   `data/2024/normalized/spells.json`.
6. **Перейменування збігаються з джерелом**: кожна пара `spellRenames2014To2024` є записом
   `kind: "renamed"` з `old2014EngName` у `spells.json`, і в реєстрі немає зайвих.

Червоний для кожного пункту, тимчасово в реєстрі:

| Правка | Падає |
|---|---|
| `{ "subclass": "THE_GENI" }` | 1 — такого підкласу 2014 немає |
| `COLLEGE_OF_LORE` під `BARD_2014` / `BARD_2024` | 2 — назва зайнята під класом 2024 |
| `FIEND` під `WARLOCK_2014` / `WARLOCK_2024` | 3 — перевиданий як Fiend Patron |
| `source: "TCE"` | 4 — не значення enum |
| прибрати `spellRenames2014To2024` | 5 — Branding Smite без рядка 2024 |
| `"Feeblemind": "Befuddlement"` у перейменуваннях | 6 — зайва пара, у списках її немає |

Записати в журнал, що кожен пункт доведено.

## Журнал

**2026-09-25 — KR закрито.**

Зроблено: `data/2024/legacy-subclasses.json` (чотири покровителі, одне перейменування),
`src/rules/legacy-subclasses-2024.ts`, юніт-тест `src/rules/legacy-subclasses-2024.test.ts` і гейт
`tests/content/legacy-subclasses-2024-registry.test.ts`. Гейт лежить у `tests/content/`, тож
`vitest.config.mts` підхоплює його сам; у списки інтеграційних файлів він не входить — бази не читає.

Що зʼясувалось:

- `SUBCLASS_SEED_INPUTS` не експортується; гейт читає його через наявний `readSubclassSeedInputs()`
  (так само робить `catalog-prose-2014.test.ts`).
- У 5etools у чорнокнижника рівно два записи на кожен старий підклас (`classSource` `PHB` і
  `XPHB`), і `reprintedAs` мають лише Archfey, Fiend, Great Old One, Celestial і Undead. Чотири
  пілоти перевидань не мають — реєстр із цим збігається.
- Пункт 3 шукає запис 5etools не лише за `shortName`, а й за книгою реєстру (`TCOE → TCE`,
  `XGTE → XGE`, `SCAG`, `PHB`). Без цього «Відьмацький клинок» із хибною книгою пройшов би
  гейт. Мапа книг задана в тесті явно, як і мапа `shortName`; підклас, якого немає в мапі
  `shortName`, валить пункт 3 окремою перевіркою, а не проходить мовчки.
- Пункт 5 додатково вимагає, щоб кожен легасі-покровитель мав список у
  `warlock-expanded-spell-lists.json`: без списку пункт зелений на порожньому наборі.
- У `spells.json` 2024 перейменувань три (Branding Smite, Summon Draconic Spirit, Feeblemind);
  у списках пілотів трапляється лише Branding Smite (Hexblade), решта списку — 55 назв — має
  рядок 2024 з тим самим `engName`.

Червоне доведено (кожна правка — у файлі з поверненням з резервної копії, `cmp` підтвердив
