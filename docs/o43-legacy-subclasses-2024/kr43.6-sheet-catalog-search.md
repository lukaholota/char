# KR43.6 — Лист, модалки класу, каталог `/2024/classes`, пошук

**Ціль:** [O43](README.md) · **Статус:** 🔵 заплановано · **Рішення:** [Р52](../DECISIONS.md#р52) — каталог показує легасі окремим блоком, пошук — ні ·
**Залежить від:** [KR43.3](kr43.3-generators-and-gates.md)

Відповідь власника 2026-09-25 ([Р52](../DECISIONS.md#р52)): каталог показує легасі окремим блоком «Зі
старих книг» з назвою книги, глобальний пошук — ні.

## Що вже працює без правок (перевірено дослідженням 2026-09-25)

- **Риси на листі** — з рядків `pers_feature`, які пише майстер (`src/server/db/pers-sheet-include.ts:31-60`,
  `pers-actions.ts:772-805`). Легасі-риси — звичайні рядки `feature`.
- **Лічильники** — `calculateMaxUsesForFeature` (`src/lib/logic/feature-resources.ts:98-150`) бере рівень
  класу через `subclassFeatures[].subclass.classId`; легасі-звʼязок веде на `WARLOCK_2024`, тож
  «Щупальце безодні» рахує бонус майстерності правильно.
- **PDF** — риси з `getCharacterFeaturesGrouped` (`src/server/pdf/generateCharacterPdf.ts:1082-1086`), назви
  підкласу не друкує взагалі (`:492-497`). Правок немає; фікстура KR43.7 лише перевіряє, що друк
  легасі-персонажа не падає.

## Кроки

### 1. Модалки підкласів на листі й у майстрі

- `loadClassSubclasses` (`src/server/db/class-content.ts:26-48`) — `where: { classId }` без фільтра,
  тож легасі вже прийдуть. Додати в `select` `class: { select: { name: true } }` і в результат
  `legacySource` через `findLegacySubclass2024(class.name, name)`; тип `ClassSubclass` — поле
  `legacySource: string | null`.
- `ClassInfoModal` (`src/lib/components/characterCreator/modals/ClassInfoModal.tsx`) — список
  підкласів ділиться тим самим `splitSubclassesForStep` з KR43.4 (`showLegacy = true`): блок
  «Зі старих книг» унизу, з `SourceBadge`. Модалку відкривають лист (`FeaturesHeaderCards.tsx:118`,
  `asyncFetchSubclasses`) і майстер (`LevelUpWizard.tsx:1592`, з контенту — там `legacySource` дає KR43.3).
- `SubclassInfoModal` — те, що зробив KR43.4 (книга + примітка про зсув), тут лише перевірити на
  листі (`FeaturesHeaderCards.tsx:135-160`).
- Шапка листа (`FeaturesHeaderCards.tsx:135-160`): під назвою легасі-підкласу — дрібний рядок з назвою
  книги (`sourceTranslations`). Потрібні дані: `legacySource` у тому, що шапка вже отримує про
  підклас; взяти з `findLegacySubclass2024` на сервері поруч із `collectPersSubclassNames`
  (`src/lib/logic/pers-class-names.ts:13`), не тягнути реєстр у клієнт окремим імпортом без потреби.

### 2. Каталог `/2024/classes`

- `ClassDetailCard.tsx:65-90`: розділити `characterClass.subclasses` на `legacy === false` і `true`.
  Заголовок секції рахує лише перші: «Підкласи (6) · з 3 рівня». Під ними — секція «Зі старих книг
  (4)» з рядком: «Правила 2024 дозволяють підклас із книги 2014 без перевидання; риси нижче 3-го
  рівня ви отримуєте на 3-му». Рендер картки підкласу — той самий, без копії розмітки (винести в
  маленький компонент, якщо його ще немає).
- Рівні рис у картці вже правильні: `classes.json` бере `levelGranted` зі зсунутих звʼязків.
- `ClassesClient.tsx:55-62,274` — пошуковий рядок каталогу містить назви підкласів; легасі теж
  шукаються всередині каталогу 2024 — це бажано. Лічильник (`:274`) — лише не-легасі.
- `jump=<slug>` у посиланні (`src/lib/omniSearchData.ts:313-316`) веде на `jumpTargetAttributes.target(slug)` —
  легасі-картка має свій таргет так само.

### 3. Глобальний пошук

- `collectSubclassItems` (`src/lib/omniSearchData.ts:660-678`): для 2024 пропускати `subclass.legacy`.
  Той самий «Джин» знаходиться в 2014, два однакові рядки в `Cmd+K` лише плутають.
- Тест поруч із наявними тестами пошуку (`rg -l "collectSubclassItems\|omniSearch" tests src`):
  «Джин» у 2024-видачі відсутній, у 2014 — є. Червоний: прибрати фільтр.

### 4. Тести

- Компонентний `ClassDetailCard`: дві секції, лічильник без легасі, бейдж книги.
- `ClassInfoModal`: блок легасі внизу.
