# KR43.5 — Розширений список покровителя, рід джина, Branding → Shining Smite

**Ціль:** [O43](README.md) · **Статус:** 🔵 заплановано · **Рішення:** [Р52](../DECISIONS.md#р52) — розширений список, у межах ліміту ·
**Залежить від:** [KR43.2](kr43.2-seed.md)

Власник 2026-09-25 обрав «**розширений список**» ([Р52](../DECISIONS.md#р52)). Відхилена альтернатива —
в кінці, лише як запис, чому не так.

## Що книга каже

Кожен із чотирьох підкласів 2014 (TCoE, XGtE, SCAG): «Your patron lets you choose from an
expanded list of spells when you learn a warlock spell. The following spells are added to the
warlock spell list for you.» Для чорнокнижника 2024 «learn» стає «prepare»: заклинання списку
покровителя готуються **в межах ліміту** підготовлених, як будь-яке заклинання чорнокнижника.

## Як це зараз у коді

- 2014: список покровителя — рядки `spell_classes` з `className = "Джин"` і `ruleset = RULES_2014`
  (`prisma/seed/subclassSpellLists2014.ts`); `findSpellLists2014` додає його лише для
  `WARLOCK_2014` (`src/rules/class-spell-choices-2014.ts:48,82-91`).
- 2024: `findOfferAllowance2024` → `buildClassSpellFilters` (`src/rules/class-spell-choices-2024.ts:147-162`)
  знає тільки список класу (і підміну для Потойбічного лицаря / Містичного спритника). Список
  покровителя не підмішується ніде.
- Кандидати читає `loadSpellChoiceOptions` (`src/server/db/spell-choice-options.ts:16-54`) за
  `spellClasses.some({ className in lists, ruleset })`, а клієнт повторно фільтрує тими ж списками
  (`isSpellChoiceCandidate`, `src/rules/spell-choice-filter.ts:47-51`).
- Фільтр роду джина вмикається лише для 2014 (`src/server/db/class-spell-choices.ts:139`).
- **Знахідка:** вибір заклинань на підвищенні отримує лише опції **класу**:
  `chosenClassOptionIds` = опції персонажа + `input.classChoiceOptionIds` / `classChoiceSelections`
  (`src/server/db/levelup-persistence.ts:311`, `:1171-1174`). Рід джина, обраний **тим самим**
  підвищенням, фільтр не бачить — і в показі, і в серверній перевірці. Для 2014 це сьогодні
  трапляється на мультикласі в чорнокнижника-джина; для легасі-джина 2024 — **завжди** (рід і
  заклинання обираються разом на 3-му).

## Чому не рядки в `spell_classes`

`spellSeed2024` перестворює `spell_classes` кожного заклинання з `data/2024/normalized/spells.json`
(`prisma/seed/spellSeed2024.ts:71-82`) — рядки «Джин» 2024 зникли б на першому пересіві. Дописати
«Джин» у `classes[]` файлу `spells.json` — значить протягти легасі у фасети каталогу 2024 і в
дзеркало 5etools, яке цей файл і наповнює. Список уже лежить у
`data/2014/warlock-expanded-spell-lists.json`; правило читає його напряму, як уже робить
`genie-kind-spells-2014.ts`.

## Кроки

### 1. Правило списку `src/rules/legacy-patron-spells-2024.ts`

```ts
export type ExtraSpellList = { name: string; spellEngNames: readonly string[] };

export function findLegacyPatronSpellList(class2024: string, subclass: string | null): ExtraSpellList | null
```

- `null`, якщо підклас не легасі (реєстр KR43.1) або його немає у
  `warlock-expanded-spell-lists.json`.
- `name` = `subclassTranslations[subclass]` («Джин») — та сама назва, що в 2014-списку й бейджі.
- `spellEngNames` — усі заклинання списку через `findSpellEngName2024` (Branding Smite → Shining Smite).
  Рід джина тут **не** фільтрується: це робить наявний `collectOtherGenieKindSpellNames` (крок 4),
  щоб правило роду було одне.

Юніт-тест: Hexblade містить `Shining Smite` і не містить `Branding Smite`; Genie — 26 назв;
`FIEND_PATRON` і `THE_GENIE` під `WARLOCK_2014` → `null`.

### 2. Фільтр отримує додатковий список

- `SpellChoiceFilter` (`src/rules/spell-choice-filter.ts:17-21`) — опціональне
  `extraList?: ExtraSpellList`.
- `isSpellChoiceCandidate` — без змін: кандидат із додаткового списку прийде з `spellLists`, що
  містить `extraList.name` (крок 3), а `listAllowedSpellLists` уже поверне його серед дозволених.
- `buildClassSpellFilters` (`class-spell-choices-2024.ts:147`) — вхід `extraList: ExtraSpellList | null`;
  для `spells`: `spellList: [base, extraList.name]`, `extraList`. Замовляння не чіпати — у списках
  покровителів їх немає.

### 3. `loadSpellChoiceOptions` читає додатковий список

- `where`: коли є `filter.extraList` — замість одного `spellClasses.some(…)`
  `OR: [{ spellClasses: { some: { className: { in: базові списки }, ruleset } } }, { engName: { in: extraList.spellEngNames } }]`;
  решта умов (`ruleset`, `level`, `schools`, `ritualOnly`, `onlySpellIds`) — як були, поруч з `OR`.
- `spellLists` у рядку: `[...spellClasses, extraList.name]` для заклинань, чий `engName` у списку.
- Юніт/інтеграційний тест у `tests/db/` — див. крок 7.

### 4. `class-spell-choices.ts`

- `findOfferAllowance2024` (`:167-184`): `extraList = findLegacyPatronSpellList(className, subclassName)`;
  передати в `buildClassSpellFilters`; `spellListNote` — той самий текст, що в 2014: «зі свого
  списку й розширеного списку покровителя «Джин»». Текст винести з `describeSpellListNote2014`
  (`class-spell-choices-2014.ts:97`) у спільну функцію, а не копіювати.
- Рід джина (`:139`): прибрати умову `ruleset === "RULES_2014"`. Опції «Genie Kind: …» існують лише
  в «Джина», тож для решти персонажів 2024 множина порожня; назви заклинань роду однакові в обох
  редакціях (усі 26 — `kind: unchanged`).

### 5. Рід джина доходить до вибору заклинань тим самим підвищенням

- `loadPersLevelUpSpellOffer` (`levelup-persistence.ts:287-313`): вхід `LevelUpSpellOfferInput`
  отримує `subclassChoiceOptionIds`; додати їх у `chosenClassOptionIds`. Майстер передає обрані
  опції підкласу (`subclassChoiceSelections` у стані) туди ж, куди вже шле `classChoiceOptionIds`.
- `executeLevelUp` (`:1171-1174`): додати `...flattenSelections(subclassChoiceSelections)` у
  `chosenClassOptionIds` перевірки `findClassSpellProblem`. Змінна вже є — `:694`, її розгортають
  для валідації опцій на `:698` і `:738`.
- Це закриває й сьогоднішню діру 2014 (мультиклас у джина). Перед правкою — characterization:
  чорнокнижник-джин 2014 мультикласом, рід Дао, спроба взяти Thunderwave (Djinni) — сьогодні
  проходить; після — відмова. Записати в журнал як виправлений баг 2014.

### 6. Риса «Розширений список заклинань» зі списком 2024

Текст 2014-рис («Expanded Spell List (Hexblade)», «Genie Expanded Spells», …) посилається на
заклинання 2014 (`/spell/1302`) і на Branding Smite. Легасі-рядок отримує **свою** рису:

- реєстр KR43.1 — поле `expandedSpellsFeature2014` у кожному записі (engName риси 2014, яку треба
  замінити);
- план KR43.2 — замість звʼязку з рисою 2014 звʼязок з рисою
  `"<engName підкласу 2014>: Expanded Spell List (legacy 2024)"` (глобальна унікальність
  `Feature.engName`, `feature-eng-names-unique.test.ts`) на рівні 3;
- назва українською — як у 2014-рисі; опис **генерує сід із файлів** ([Р33](../DECISIONS.md#р33):
  файл є — `warlock-expanded-spell-lists.json` + реєстр) у форматі 2014-риси: `1р. <a href="…">Назва [Eng]</a>, …`,
  посилання — `/2024/spells/<slug>` через `buildSpellSlug` (`src/lib/spell-link.ts:18`; не
  `spellsData` — памʼять про 1,8 МБ); для «Джина» — спільні рядки, потім по рядку на рід;
- прогнати `tests/content/glossary-marker.test.ts` і `rule-term-mentions-linked.test.ts` — якщо
  гейт сканує сід, згенерований текст має його проходити.

### 7. Лист

- `AddSpellDialog.tsx:336-349` і `MagicSlide.tsx:670-688` будують `/2024/spells?sub=Джин`. У каталозі
  2024 такого списку немає — фільтр дасть порожньо. Для легасі-підкласу посилання `sub=` не
  будувати; список гравець бачить у рисі з кроку 6.
- Лічильник підготовлених: заклинання зі списку покровителя обирається з бейджем класу й
  рахується в ліміт (`countOwnedClassSpells`, `class-spell-choices-2024.ts:124`) — як і має бути
  для розширеного списку. Тест це пришпилює.

### 8. Тести

`tests/db/legacy-patron-spells-2024.test.ts` (обидва інтеграційні конфіги), один `beforeAll` на
фікстури ([Р45](../DECISIONS.md#р45) правило 2):

| Персонаж | Перевірка |
|---|---|
| Чорнокнижник 2024 3, Джин, рід Дао (тим самим підвищенням) | пропозиція містить Sanctuary, Spike Growth, Phantasmal Force; **не** містить Thunderwave, Gust of Wind; базовий список на місці; `spellListNote` про «Джин» |
| той самий, спроба взяти Thunderwave | `executeLevelUp` відмовляє |
| Чорнокнижник 2024 3, Відьмацький клинок | Shining Smite 2024 є серед кандидатів; жодного `spell.ruleset = RULES_2014` |
| Чорнокнижник 2024 3, Безодня | Create or Destroy Water, Thunderwave, Gust of Wind, Silence |
| Чорнокнижник 2024 3, Fiend Patron | пропозиція дорівнює сьогоднішній — список покровителя не підмішався |

Червоні: прибрати `extraList` (падає перший рядок), повернути умову 2014 на роді (падає «не
містить Thunderwave»), прибрати опції підкласу з `chosenClassOptionIds` (падає відмова).

## Відхилено: «завжди підготовлені» (для історії)

Замість кроків 1–4: рядки `subclass_spell` у плані KR43.2 з `class_level` за рівнем заклинання
(1-й і 2-й → 3, 3-й → 5, 4-й → 7, 5-й → 9 — таблиці в тексті 2014 немає, це наша побудова,
і її треба записати рішенням), з обмеженою зачисткою `subclassSpells2024` (KR43.2 крок 1).
Видача — наявним шляхом `findMissingSubclassSpells` (`always-prepared-spell-grants.ts:29-56`), поза
лімітом. Рід джина тоді треба вчити `findEarnedAlwaysPreparedSpells`, бо він не знає опцій. Кроки
5–7 лишаються.
