# KR43.2 — Сід легасі-рядків під класом 2024

**Ціль:** [O43](README.md) · **Статус:** 🟡 код і локальна база готові, бракує контрольного прогону сіду рис 2014 · **Залежить від:** [KR43.1](kr43.1-registry.md) ·
**База:** локальна `spells_test` (`.env.test`), прод — лише після викатки [KR43.3](kr43.3-generators-and-gates.md)

## Що має зʼявитися в базі

Для кожного запису реєстру — рядок `subclass` під класом 2024 і його звʼязки. Для «Джина»:

| Таблиця | Рядок | Звідки |
|---|---|---|
| `subclass` | `class_id = WARLOCK_2024`, `name = THE_GENIE`, `ruleset = RULES_2024`, `spellcasting_type = NONE`, `grants_spells = false`, `primary_casting_stat = NULL`; `description`, `languages*`, `tool*`, `armor_proficiencies`, `weapon_proficiencies` — копія рядка 2014 | рядок 2014 |
| `subclass_feature` | ті самі `feature_id`, що в 2014, `level_granted = shiftLegacyLevel(рівень, 3)`, `grants_spell_slots` — копія, `ruleset = RULES_2024` | звʼязки 2014 |
| `subclass_choice_option` | ті самі `choice_option_id` (4 роди джина), `levels_granted = shiftLegacyLevels([1], 3) = [3]`, `ruleset = RULES_2024` | звʼязки 2014 |
| `subclass_spell` | копія рядків 2014 з `class_level = shiftLegacyLevel(…)`; **для чотирьох покровителів їх немає** | звʼязки 2014 |

Чому `spellcasting_type = NONE`: так записані всі підкласи 2024 (`prisma/seed/subclassSeed2024.ts:86`);
чаклування дає клас, а тип класу має пріоритет (`src/rules/spellcasting.ts:67-73`). `PACT` з рядка
2014 шкоди не зробив би, але зламав би порівняння в `subclass-spellcasting-2024.test.ts`.

Чому ті самі `feature_id` і `choice_option_id`: див. рішення 2 у [README](README.md#як-це-влаштовано-рішення-цілі).
`choice_option.option_name_eng` глобально унікальний (`schema.prisma:80`), тож дублювати роди
джина й неможливо, і не треба. `Feature.ruleset` ніде в `src/` не читається (перевірено grep).

## Кроки

### 1. Зачистка сідів, що шукають підклас лише за назвою — **той самий коміт, до першого рядка**

- `prisma/seed/subclassFeatureSeed.ts:10196-10200` — `prisma.subclass.findMany({ select: … })`
  без фільтра; `Map(name → subclassId)` віддає останній рядок. Додати
  `where: { ruleset: "RULES_2014" }` (сід пише лише риси 2014).
- `prisma/seed/subclassChoiceOptionSeed.ts:332` — `findFirst({ where: { name: link.subclass } })`.
  Додати `ruleset: "RULES_2014"`.
- Пройти решту: `rg -n "subclass\.(findFirst|findMany|findUnique)\(" prisma scripts` і для кожного
  виклику без `ruleset` або `classId` у `where` — або додати, або записати в журнал, чому він
  безпечний (наприклад, `subclassSpellLists2014.ts:133,144` уже фільтрує, `subclassChoices2024.ts:20`
  теж).
- `prisma/seed/subclassSpells2024.ts:98-114` — `pruneRowsMissingFromFile` видаляє кожен
  `subclass_spell` 2024 поза `subclasses.json`. Обмежити `where` підкласами, які сід справді веде:
  `subclassId: { in: [...subclassIdByEnum для записів subclasses.json] }`. Для пілота це нічого не
  міняє, але жрець/друїд/паладин у KR43.8 без цього втрачатимуть рядки на кожному пересіві 2024.

Перевірка зачистки — прогін старих сідів на клоні **після** першого легасі-рядка:
`bun run seed:subclass-spell-lists-2014:test` (показ) і повторний прогін сіду рис 2014 на копії
бази (`scripts/local-test-db.sh clone spells_scratch_test` → сід рис 2014 туди), потім запит:
жодного `subclass_feature`, де `subclass.ruleset = RULES_2024`, а `feature.engName` не з легасі-плану.

### 2. Чистий план `prisma/seed/helpers/legacySubclassPlan.ts`

Сід = завантажити → спланувати → показати/записати. Планування чисте, щоб тестуватися без бази.
Живе поруч із `choiceOptions2024.ts`, а не в `src/rules/`: це план запису, а не правило гри.

```ts
export type LegacySubclassSource = {           // рядок 2014 як його читає сід
  subclass: string;
  description: string | null;
  languages: string[]; languagesToChooseCount: number;
  toolProficiencies: string[]; toolToChooseCount: number | null;
  armorProficiencies: string[]; weaponProficiencies: unknown;
  features: { featureId: number; engName: string; levelGranted: number; grantsSpellSlots: boolean }[];
  choiceOptions: { choiceOptionId: number; levelsGranted: number[] }[];
  spells: { spellId: number; classLevel: number }[];
};

export type LegacySubclassPlan = {
  subclass: string; class2024: string;
  row: { /* колонки subclass для upsert */ };
  features: { featureId: number; levelGranted: number; grantsSpellSlots: boolean }[];
  choiceOptions: { choiceOptionId: number; levelsGranted: number[] }[];
  spells: { spellId: number; classLevel: number }[];
};

export function planLegacySubclass(source: LegacySubclassSource, entry: LegacySubclass2024, subclassLevel2024: number): LegacySubclassPlan
```

Юніт-тест `tests/content/legacy-subclass-plan.test.ts` (юніт-конфіг включає `tests/content/**`) на фікстурі «Джина» (рівні 1,1,6,10,14;
вибір `[1]`) і «Відьмацького клинка» (володіння): рівні `[3,3,6,10,14]`, вибір `[3]`,
`spellcastingType: "NONE"`, володіння скопійовані, `ruleset` — 2024. Червоний: прибрати зсув.

KR43.5 додасть у план заміну риси «Expanded Spell List (…)» на легасі-рису зі списком 2024 —
тому `features` у плані будується функцією, куди ця заміна лягає одним кроком.

### 3. Сідер `prisma/seed/legacySubclasses2024.ts` і скрипт

- `scripts/seed-legacy-subclasses-2024.ts` за зразком `scripts/seed-2014-subclass-spell-lists.ts`:
  `--target test|prod`, **без `--apply` лише друкує план** (що створиться, що оновиться, що
  видалиться), з `--apply` пише однією транзакцією на підклас.
- `package.json`: `seed:legacy-subclasses-2024:test`, `seed:legacy-subclasses-2024:prod`.
- Кроки сідера:
  1. `loadLegacySources` — для кожного запису реєстру рядок 2014
     (`where: { name, ruleset: "RULES_2014", class: { name: class2014 } }`) з `features`,
     `subclassChoiceOptions`, `preparedSpells`; клас 2024 з `subclassLevel`. Немає — помилка з назвою.
  2. `planLegacySubclass` на кожен.
  3. `writeLegacySubclass` — upsert `subclass` на `classId_name`; upsert `subclass_feature` на
     `[subclassId, featureId]`; upsert `subclass_choice_option` на `unique_subclass_choice`; upsert
     `subclass_spell` на `unique_subclass_spell`; **видалити** звʼязки легасі-рядка, яких немає в
     плані (лише цього рядка — сід ідемпотентний і переживає зміну плану).
- Персонажів і `pers_*` не чіпає.

## Журнал

**2026-09-25 — код, локальний прогін і тести готові; бракує однієї перевірки зачистки.**

Зачистка — чотири місця з плану плюс прохід `rg`:

| `subclassFeatureSeed.ts` — `Map(name → subclassId)` | `where: { ruleset: "RULES_2014" }` |
| `subclassChoiceOptionSeed.ts` — `findFirst({ name })` | `+ ruleset: "RULES_2014"`. Пілотів цей сід не торкається, але KR43.8 торкнеться |
| `subclassSpells2024.ts` — `pruneRowsMissingFromFile` | видаляє лише рядки підкласів із `subclasses.json` (`collectFileSubclassIds`) |
| `rg` по `prisma/`, `scripts/` | безпечні: `subclassSpellLists2014.ts:133,144`, `catalogProse2014.ts:57,59`, `sweptTermText2014.ts:99,132`, `subclassChoices2024.ts:19`, `subclassSpells2024.ts:57` — фільтрують редакцію; `radiantTerminology.ts:120` без редакції пише той самий виправлений текст і в копію опису легасі-рядка — розбіжності не дає; `scripts/terms/verify-radiant-db.ts:23` лише читає |

Код:

- `prisma/seed/helpers/legacySubclassPlan.ts` — чистий план (`planLegacySubclass`) і різниця з базою
  (`diffLegacySubclass`, `isLegacySubclassDiffEmpty`). Показ без `--apply` — це і є різниця.
  Звʼязок риси несе `engName`: показ читабельний, і KR43.5 знайде за ним «Expanded Spell List».
- `prisma/seed/legacySubclasses2024.ts` — завантажити → спланувати → різниця → запис однією
  транзакцією на підклас; видаляє лише звʼязки самого легасі-рядка. Рядок 2014 шукає за
  `name + RULES_2014 + class`, клас 2024 — за `name + RULES_2024`, і кидає, якщо рядків не рівно один.
  `weaponProficiencies: null` пише як `Prisma.DbNull`.
- `scripts/seed-legacy-subclasses-2024.ts`, `seed:legacy-subclasses-2024:test|prod` у `package.json`.
- `prisma/seed/**` виключено з `tsconfig.json`, тож `tsc` сідер не бачить. Типи перевірено окремим
  `tsconfig`, що розширює кореневий і включає нові файли, — 0 помилок.

Локальний прогін (`spells_test`, 127.0.0.1:5433): показ — 4 створення; `--apply`; повторний показ —
«0 з 4 підкласів мають зміни». Запит на `pg`: 4 рядки `RULES_2024` / `NONE` під `WARLOCK_2024`;
Джин — ті самі `feature_id`, рівні 1,1,6,10,14 → 3,3,6,10,14, чотири роди на `[3]`; Відьмацький
клинок — `{MEDIUM,SHIELD}` і `["MARTIAL_WEAPON"]`; жодної легасі-риси не з рядка 2014; знімок
`subclass_feature`/`subclass_choice_option`/`subclass_spell`/`subclass` 2014 до й після однаковий.
`seed:subclass-spell-lists-2014:test` після легасі-рядків — показ `+0 / −0`.

**Контрольний прогін сіду рис 2014 на копії бази — зроблено 2026-09-25** (спершу його блокував
автоматичний режим, власник дав прямий дозвіл). Одноразовий скрипт: `spells_scratch_test` заново
