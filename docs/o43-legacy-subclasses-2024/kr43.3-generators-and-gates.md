# KR43.3 — Генератори й гейти знають про легасі-підкласи

**Ціль:** [O43](README.md) · **Статус:** 🟡 код готовий, на прод не викатано · **Залежить від:** [KR43.1](kr43.1-registry.md) ·
**Викатити на прод раніше, ніж сід KR43.2 піде в прод** — див. «Навіщо»

## Навіщо

Щойно на робочій базі зʼявиться перший легасі-рядок, **наступна збірка впаде**:
`prebuild` = `generate:content` → `generate:classes` → `findSubclassSource` кидає
`No source for 2024 subclass WARLOCK_2024/THE_GENIE` (`scripts/generate-classes.ts:83-91`). Тому
цей KR — код, який має бути на проді **до** сіду, і сам по собі нічого не змінює, доки легасі-рядків
у базі немає (гейти червоніють лише на регенерованому контенті).

Друга частина — позначка легасі в згенерованому контенті: з неї майстер (KR43.4) і каталог
(KR43.6) знають, що ховати за перемикачем і що підписати книгою.

## Кроки

### 1. `scripts/generate-classes.ts` → `src/lib/generated/classes.json`

- `findSubclassSource(classKey, subclassKey, ruleset)`: перед пошуком у `subclasses2024` —
  `findLegacySubclass2024(classKey, subclassKey)?.source`. Кидати, як і досі, коли підкласу немає
  ні там, ні там.
- `GeneratedSubclass` (`:48-56`) отримує `legacy: boolean` — `isLegacySubclass2024(classKey, subclassKey)`
  для 2024, `false` для 2014.
- Назва: `findSubclassName` (`:105-116`) для 2024 шукає `THE_GENIE_2024`, потім `THE_GENIE` →
  «Джин» / «The Genie». Новий ключ у `translation.ts` **не потрібен** — і не заводити
  (`dictionary-mirrors-translation.test.ts` вимагатиме дзеркала).
- `slug` підкласу береться з `engName` — «the-genie» живе під `/2024/classes`, «the-genie» 2014 —
  під `/classes`; маршрути розділені, конфлікту немає.

### 2. `src/server/db/creator-content-query.ts` → `creator-content-2024.json`

- Після `findCreatorClasses` (`:74-80`) — крок `markLegacySubclasses(classes)`: кожен підклас отримує
  `legacySource: string | null` = `findLegacySubclass2024(class.name, subclass.name)?.source ?? null`.
  Для 2014 завжди `null`.
- Тип: `SubclassI` (`src/lib/types/model-types.ts:708`) — `legacySource?: string | null`.
  Опціональне, бо `SubclassI` будують і з рядків Prisma напряму; **без `as any`**.
- Чому не колонка в базі: див. рішення 3 у [README](README.md#як-це-влаштовано-рішення-цілі).

### 3. Гейти, що рахують підкласи 2024 як `subclasses.json`

Кожен переписати так, щоб він рахував **`subclasses.json` + реєстр** і далі ловив справжню
розбіжність. Не послаблювати до `>=`.

| Файл | Зараз | Стане |
|---|---|---|
| `tests/content/subclass-spellcasting-2024.test.ts:45-51` | усі підкласи `creator-content-2024.json` = `subclasses.json` (76) | порівнювати лише `legacySource === null`; окремий `it`: легасі — рівно реєстр, у кожного `spellcastingType: "NONE"`, `primaryCastingStat: null` |
| `tests/content/catalog-prose-2014.test.ts:35,88` | `SUBCLASSES_2024 = 76` описаних у `classes.json` | `76 + LEGACY_SUBCLASSES_2024.length`; опис легасі — копія 2014, тож він і так є |
| `tests/content/ruleset-2024-isolation.test.ts:60` (база) | `subclass.count(RULES_2024) === normalizedSubclasses.length` | `=== normalizedSubclasses.length + LEGACY_SUBCLASSES_2024.length` |
| `tests/content/subclass-catalog-source.test.ts` | контракт `findSubclassSource` | + `findSubclassSource("WARLOCK_2024", "THE_GENIE", "RULES_2024") === "TCOE"`; `"UNKNOWN"` і далі кидає |

`catalog-prose-2024.test.ts` читає `subclasses.json` напряму — не чіпається. `rules2024-import.test.ts`
перебирає лише `subclasses.json` — теж.

Ще раз пройти: `rg -n "subclasses2024|normalizedSubclasses|subclasses\.json|toHaveLength\(76\)|\b76\b" tests src scripts`
і для кожного збігу, що рахує **згенерований** контент або **базу**, вирішити так само. Список —
у журнал.

### 4. Регенерація і перевірка без прод-сіду

1. Сід KR43.2 на локальну базу (`--apply`).
2. `bun tsx scripts/generate-creator-content.ts --target test` і `generate:classes` проти
   тієї ж бази — **не комітити** цей результат: закомічений контент має приходити з робочої бази.
   Перед регенерацією — копія файлів (памʼять «Копія generated-файлу до регенерації»), щоб
   побачити diff: зʼявилися чотири підкласи з `legacySource`/`legacy`, решта байт-у-байт.
3. На цьому контенті — `bun run test:no-db` і `tests/content/*` зелені; на закоміченому
   (без легасі) — теж зелені.
4. Повернути закомічені файли з копії.

Червоний для кожного гейта з кроку 3: на регенерованому контенті відкотити відповідну правку
тесту — він має впасти саме на легасі-рядках.

## Журнал

**2026-09-25 — код і гейти готові, на прод не викатано.**

Код:

- `scripts/generate-classes.ts`: `findSubclassSource` спершу питає реєстр
  (`findLegacySubclass2024(...)?.source`), далі — `subclasses.json`, і так само кидає, коли немає
  ніде. `GeneratedSubclass.legacy: boolean`. Назви легасі беруться з наявних `THE_GENIE` →
  «Джин» / «The Genie» тощо — нових ключів у `translation.ts` немає.
- `src/lib/classesData.ts`: `SubclassData.legacy?: boolean` — необовʼязкове, як `source`, бо
  закомічений `classes.json` до першої регенерації після прод-сіду поля не має.
- `src/server/db/creator-content-query.ts`: `findCreatorClasses` додає кожному підкласу
  `legacySource` (`markLegacySubclasses`); тип `CreatorClassWithLegacy` без `as any`, поле
  необовʼязкове з тієї ж причини. `SubclassI.legacySource?: string | null`.

Гейти (крок 3):

| Файл | Що стало |
|---|---|
| `subclass-spellcasting-2024.test.ts` | звірка з `subclasses.json` — лише підкласи без `legacySource`; новий `it`: легасі або немає, або рівно реєстр (клас, назва, книга), і всі `NONE`/`null` |
| `catalog-prose-2014.test.ts` | `SUBCLASSES_2024 = 76` рахує лише не-легасі; легасі — `0` або `N`, і кожен з описом |
| `subclass-catalog-source.test.ts` | `+ THE_GENIE 2024 → TCOE`, `THE_GENIE 2014 → null`; `UNKNOWN` і далі кидає |
| `ruleset-2024-isolation.test.ts` + два `tests/db/*` | зроблено в KR43.2 |

Форма «або жодного, або рівно реєстр» — свідома: у CI гейти читають закомічений контент, а він до
прод-сіду легасі не має. Звузити до «рівно реєстр» — у KR43.7 після регенерації з проду.

`rg`-прохід (`subclasses2024|normalizedSubclasses|subclasses\.json|\b76\b`): решта збігів читають
сам `subclasses.json` або сирі джерела (`catalog-prose-2024`, `rules2024-import`,
`subclass-source-2024`, `subclass-feature-*-2024`, `subclass-prepared-spells-2024`,
`artificer-subclasses-2024-seeded` — лише Винахідник, `radiant-term-sweep`, `metamagic-2014-source`,
`feat-terms-in-prose-2024`) — легасі-рядки їх не зачіпають. `catalog-prose-carrier.test.ts:27`
(`76`) — це раси.

Регенерація (крок 4) — на **копії дерева** в scratchpad (APFS-клон без `.env`, `node_modules`
посиланням), щоб не підмінити `src/lib/generated/` під паралельною сесією; закомічені файли не
чіпались і відновлювати нічого не довелось. Проти локальної `spells_test` з легасі-рядками:

- `classes.json`: 26 класів, 198 підкласів (118 + 76 + 4). Без чотирьох легасі й поля `legacy` —
  **рівно** закомічений файл. Легасі: Безодня, Відьмацький клинок, Джин, Невмирущий з книгами
  TCOE / XGTE / TCOE / SCAG.
- `creator-content-2014.json`: без `legacySource`, дат і порядку масивів — рівно закомічений.
  `creator-content-2024.json`: класи так само, плюс 4 легасі з `legacySource`; у расах 2024
  розходяться лише ID `raceChoiceOptionTraitId` (клон пересіяли) — до O43 не стосується.
  Порядок масивів різниться, бо частина `include` іде без `orderBy`, а клон віддає інший
  фізичний порядок.
- `bun run test:no-db` на цьому контенті — 396 файлів, 2 994 тести зелені.
