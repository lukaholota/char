# KR14.2 — 473 сторінки aidedd: стягування, парсер, маніфест

**Ціль:** [O14](README.md) · **Статус:** ✅ (2026-08-23) · **Залежить від:**
[KR14.1](kr14.1-single-source.md) і рішення власника
[2](README.md#відкриті-питання-потрібне-рішення-власника) (політика розпилу варіантів)

## Мета

Мати на диску 473 сторінки предметів у сирому HTML, парсер, що перетворює їх у наш запис, і
маніфест, який тримає стан 16 партій між сесіями. Після цього KR жодна наступна сесія не
ходить у мережу за даними — тільки за перевіркою.

## Що вже є і чого не треба робити

`scripts/aidedd/aidedd-catalogs.ts` містить готовий каталог `magic-items-2014`: `expectedCount`
473, `listUrl` `https://www.aidedd.org/dnd-filters/magic-items.php`, усі значення селектів
перелічені явно (9 типів × рідкості `C, NC, R, TR, L, A` × джерела `base, xgte, tcoe, ftod,
gog, bmt, adv`), `buildPageUrl` → `https://www.aidedd.org/dnd/om.php?vo=<slug>`.
`data/aidedd/lists/magic-items-2014.json` уже несе 473 слаги.
`fetch-pages.ts` працює з `--catalog=magic-items-2014` **без правок**.

`data/aidedd/raw/magic-items-2014/` **не існує — стягнуто 0 сторінок.**

Пастка з фільтрами описана в
[O12](../o12-srd-2024-import/README.md#пастка-з-фільтрами--головне-на-чому-тут-можна-недорахуватися)
і вже ловила проєкт двічі: дефолт сторінки ≠ «усе». Тому `fetch-list` мусить падати на
кількості, відмінній від 473, а не тихо писати менший перелік.

## Узгоджений scope

1. **Перезняти перелік** `fetch-list.ts --catalog=magic-items-2014` і підтвердити 473 — щоб
   число в репо було свіжим, а не з розвідки 2026-08-17.
2. **Стягнути 473 сторінки** тим самим ввічливим качальником (`scripts/lib/polite-http.ts`):
   один потік, пауза, кеш у `data/aidedd/raw/magic-items-2014/`, повторний запуск не перекачує.
   Сторінка предмета — 5–7 КБ без JS, тобто ~3 МБ на весь каталог.
3. **`scripts/aidedd/parse-magic-item-2014.ts`** — HTML → запис. Сторінка простіша за статблок:
   `h1` (назва), рядок типу / рідкості / налаштування, проза опису, таблиці (`d100`-таблиці
   для колод і фігурок), джерело. Орієнтир — 200–250 рядків проти 169 + 78 + 162 + 120 у істот.
4. **Схема запису** `magic-item-schema.ts` під наявні колонки `MagicItem` плюс поля, які вже
   вміє показувати UI 2024-пулу: `typeLineEng`, `attunementConditionEng`, `isCursed`,
   `isConsumable`.
5. **Маніфест** `data/aidedd/magic-items-manifest.json` — рядок на предмет: `nameEng`, `slug`,
   `status` (`pending` → `parsed` → `translated` → `verified`), `magicItemId`, `batch`,
   розмір партії 30.
6. **Пінінг id.** Для 310 предметів, що зіставилися за назвою, `magicItemId` береться
   **з наявного каталогу**, бо це публічний URL (`/magic-items/1001`), він у
   `generateStaticParams` і в `sitemap.ts`. Нові предмети отримують id з діапазону, який не
   перетинається ні з 1–1224, ні з синтетичними 20001+ для 2024.
7. **Політика розпилу** (питання 2) відображена в маніфесті явно: рядок «одна сторінка aidedd →
   N наших записів» має бути видимий, а не схований у коді.

### 2026-08-23 — KR закрито: тести парсера в `tests/` і звірка полів на 310 збігах

Закрито рівно те, що лишалося після 2026-08-22, — решта пунктів уже була зроблена.

**1. Тести парсера переїхали в `tests/`: 19 перевірок, кожна доведена червоною.**

`tests/content/magic-items-2014-import.test.ts` іде через `bun run test` (пусті тести, без
бази). Сторінки лежать у `tests/fixtures/aidedd/magic-items-2014/` — **вісім фікстур**, а не
в `data/aidedd/raw/`: сирий кеш у `.gitignore`, і тест, який на нього спирається, помирає на
свіжому клоні. Це відрізняється від прецеденту бестіарію (`bestiary-2014-import.test.ts` читає
`data/aidedd/raw/monsters-2014/…`) — і відрізняється навмисно.

Фікстури підібрані під поведінку парсера, а не за алфавітом:

| Фікстура | Що пінить |
|---|---|
| `blackrazor` | повний запис: тип, підтип, рідкість, умова налаштування, джерело |
| `weapon-1-2-or-3` | три рідкості в одному рядку → `bundlesMultipleVariants` |
| `belt-of-giant-strength` | «rarity varies» → рідкість лишається порожньою; таблиця → GFM |
| `bag-of-tricks` | три таблиці однієї сторінки не зливаються |
| `deck-of-illusions` | `&nbsp;`-роздільники: сутності декодуються, порожні рядки лишаються |
| `ersatz-eye` | сторінка лише з резюме → `isSummaryOnly`, а не «короткий опис» |
| `wave` | єдина сторінка з порожнім `source` — і вона лишається порожньою |
| `sword-of-kas` | парсер віддає тип джерела (`WONDROUS_ITEM`), а лагодить його `SOURCE_ITEM_TYPE_OVERRIDES` |

Доведення червоним — **17 зламів у трьох файлах** (`parse-magic-item-2014.ts`,
`html-statblock.ts`, дані маніфесту й переліку), кожен відкочено побайтово (md5 звірено).
Кожна з 19 перевірок падала щонайменше на одному зламі:

| Що зламали | Що впало |
|---|---|
| знято дедуп рідкостей | «very rare» не рахується за «rare» |
| налаштування завжди `false` | blackrazor, ersatz-eye, розбір хвоста |
| маркер резюме не ловить | сторінка лише з резюме |
| роздільник GFM `---` → `:::` | таблиці стають GFM-таблицями |
| заголовок `<th>` не розпізнається | обидві таблиці |
| тип мовчки полагоджено під каталог | «не лагодить мовчки» |
| порожнє джерело замінено заглушкою | `wave` |
| named-entities не декодуються | deck-of-illusions, «немає сутностей» |
| `h1` не читається | blackrazor, belt, wave |
| підтип у дужках губиться | blackrazor, розбір хвоста |
| «varies» не розпізнається | «rarity varies» |
| з бандла лишається одна рідкість | три рідкості, порядок рідкостей |
| рядок без налаштування вважається налаштованим | «умова порожня, а не вигадана» |
| рідкості не впорядковано за шкалою | порядок рідкостей |
| відкладений рядок потрапив у партію | 473/282/191, партії по 30 |
| два предмети з одним id / новий id із наявного діапазону | унікальність і діапазон id |
| `expectedCount` зсунуто / з переліку зник слаг | перелік слагів, звірка з маніфестом |

Заразом закрито пункт про `fetch-list`: замість живого походу в мережу перевірка стоїть у
тесті — `expectedCount` 473, перелік на 473 унікальні слаги, і множина слагів переліку
дорівнює множині слагів маніфесту. Мовчазний недобір із фільтра тепер валить `bun run test`,
а не лишається непоміченим до наступного стягування.

**2. Звірка полів на збігах — те, чого бракувало найбільше.**

Пункт «тип, рідкість і `requiresAttunement` звірені на кожному збігу» стояв невиконаним.
Тепер це **розділ 6** [divergence-magic-items.md](../../data/aidedd/divergence-magic-items.md),
який збирає той самий `build-magic-items-divergence.ts` (окремого скрипта не заводили).
Розділ показує три стани поля — базовий корпус, aidedd, сід зараз, — бо інакше не видно,
хто вже виправив розхід, а хто ні.

| | Скільки |
|---|---:|
| Збігів із базовим корпусом (`baseline.json`, 472 записи) | 310 |
| Розійшлися тип / рідкість / налаштування | **15** |
| Виправлено партією за джерелом | 8 |
| Дефект джерела, свідомо відхилено (`SOURCE_ITEM_TYPE_OVERRIDES`) | 1 |
| **Лишається нерозвʼязаними** | **6** |

Вісім виправлених — це реальні дефекти каталогу, які імпорт уже зняв: `Blackrazor`, `Wave`
і `Whelm` стояли `ARTIFACT` замість `LEGENDARY`, `Helm of Brilliance` — `LEGENDARY` замість
`VERY_RARE`, `Vicious Weapon` — `UNCOMMON` замість `RARE`, а `Daern's Instant Fortress`,
`Hammer of Thunderbolts` і `Ring of Resistance` мали неправильне налаштування.

Шість нерозвʼязаних — усі однакового роду: сторінка має **лише резюме**, тобто рядок типу
на ній є, а тексту правил немає, тому предмет позначено `deferred` і в жодну партію він не
входить — виправити поле нема кому. Другого джерела в репозиторії немає: 2024-пул збігається
з нашим значенням, але саме звідти ці записи й приїхали. Винесено власникові —
[owner-decisions.md, П11](owner-decisions.md#11--шість-розбіжностей-полів-на-сторінках-лише-з-резюме).

**Чого свідомо не робилося.** У базу нічого не писалося, `seed:magic-items:*` і
`generate:content` не запускалися, `EXPECTED_CATALOG_SIZE` лишається 472, у мережу не ходили.
`magicItems.json` — 472 записи, md5 `2ba7c1b0f2042b0b2c3d9344efa45337`, той самий, що до сесії.
