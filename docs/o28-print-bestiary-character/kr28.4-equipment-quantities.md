# KR28.4 — Кількість однакового спорядження

**Ціль:** [O28](README.md) · **Статус:** ✅ · **Залежить від:** нічого

## Мета

Друкувати десять однакових списів як `Спис ×10`, а не як десять однакових рядків.

## Що саме зробити

1. Перед зміною додати characterization-тести для `fillWeapons` і `buildEquipmentText`, включно
   з нинішнім невдалим випадком десяти списів.
2. Побудувати одну чисту нормалізацію printable equipment: стабільний ключ однаковості,
   локалізована назва, кількість і всі поля, що змінюють друкований рядок.
3. Живити нормалізованим списком і три поля атак, і текст спорядження.
4. Не зливати екземпляри з різним override, шкодою, бонусами, equipped/attuned станом або іншою
   видимою кастомізацією.
5. Довести red → green: тимчасово зламати групування й показати, що тест ловить повернення
   десяти рядків, після чого відновити код.

## Готово, коли

- [x] Десять однакових списів друкуються рівно одним рядком із `×10`.
- [x] В атаках вони займають одне поле, тому дві інші різні зброї не зникають.
- [x] Один предмет не має шуму `×1`.
- [x] Два по-різному налаштовані списи лишаються двома рядками.
- [x] Порядок різних предметів стабільний і повторюваний.
- [x] Characterization-тест був перевірений на червоному за правилами проєкту.

## Журнал

- 2026-09-01: додано одну pure-функцію групування printable items із різними стабільними ключами
  для текстового спорядження й повного надрукованого рядка атаки (назва, бонус, шкода).
- 2026-09-01: `buildEquipmentText` агрегує наявні `xN`, прибирає `×1`; `fillWeapons` групує до
  відбору трьох полів, тому десять списів займають одне поле.
- 2026-09-01: characterization-тест навмисно перевірено на зламаному сумуванні: він упав із
  `Спис ×2` замість `Спис ×10`; після відновлення правильного коду 4/4 тести зелені.
