# KR28.2 — Статблок і print-проєкція

**Ціль:** [O28](README.md) · **Статус:** ✅ · **Залежить від:** KR28.1

## Мета

Зробити один повторно використовуваний друкований статблок істоти за референсом власника й одну
проєкцію описів, яка не випускає в PDF службову розмітку.

## Що саме зробити

1. Виділити тип printable creature з усіма механічними полями й групами дій, але без image URL.
2. Реалізувати макет із секції «Контракт друкованого статблока істоти» в [README](README.md):
   компактна шапка, шість характеристик, метадані, риси та наявні групи дій.
3. Дозволити довгому статблоку переноситися без накладань і без обрізання тексту; короткі
   статблоки компонувати економно на Letter/A4.
4. Виділити спільну print-проєкцію Markdown/тексту: `термін{{English}}` → `термін`; dedicated
   related/similar блоки відкидаються; видимий змістовний текст звичайних посилань лишається.
5. Підключити проєкцію до істот і чинних HTML-PDF описів заклинань, магічних предметів та рис,
   не додаючи нових друкованих каталогів.

## Готово, коли

- [x] Snapshot/structure-тест фіксує всі секції референсного статблока.
- [x] Істота без бонусних/легендарних дій не має порожніх заголовків.
- [x] Дуже довга істота не обрізається й не накладає секції.
- [x] У тексті PDF немає `{{`, `}}` та вмісту glossary-маркера.
- [x] Dedicated related items/creatures не потрапляють у PDF.
- [x] Жоден renderer не має власної копії regex для glossary-маркера.
- [x] Портрет не читається навіть як прихований base64/resource.

## Журнал

- 2026-09-01: виділено `PrintableCreature`, який фізично відкидає `imageUrl`, `imageWidth` та
  `imageHeight`; renderer будує теплий двоколонковий статблок із усіма непорожніми групами дій.
- 2026-09-01: `printProjection` повторно використовує канонічний `stripGlossaryMarkers` і
  підключений до істот, заклинань, магічних предметів та рис. Printable DB-select магічних
  предметів не завантажує related relations, а статичний printable creature не має related-поля.
- 2026-09-01: structure-тести зафіксували всі секції, порожні заголовки, відсутність marker/image.
  Runtime-preview вовка підтвердив референсну форму. Runtime-preview Тараска спочатку виявив
  невдалий `inline-block`; після переходу на block column-flow весь довгий статблок умістився на
  одній сторінці через дві колонки без обрізання чи накладань.
- 2026-09-02: за уточненням власника додано `column-fill: auto`, тому PDF спершу заповнює всю
  ліву колонку й лише тоді праву, як renderer заклинань, а не балансує дві короткі половини.
  Кремовий фон, бордові й золоті акценти замінено на білий фон, чорний текст і чорні лінії.
  Новий runtime-preview Тараска підтвердив обидві зміни.
