# Текст у полях аркуша: не губиться й не блокує сервер

## Що було

- Майстер повідомив: на класичному аркуші 2014 у полі «Інші уміння та знання мов» зникають мови.
  Поле мало фіксований кегль 7, а «Мови:» стояли останніми, тож при довгих володіннях обрізалися
  повністю. Так само обрізалися «Спорядження» (лише 14 із 40 рядків), риси характеру, ідеали,
  прив'язаності й слабкості (кегль 10, 2–3 рядки, наступний розрізаний посередині літер) і поля шапки
  (переносилися на другий рядок у полі висотою ~16 pt).
- «Лист 2024» для товстого друїда будувався 206,7 с. Причина — перенос рядків: і власний
  `splitAtWidth`, і `layoutMultilineText` pdf-lib для кожного рядка переміряють увесь залишок абзацу
  по слову за спробу, а підбір кегля повторює це для кожного кроку 0,25 pt. Один вимір NotoSans —
  0,65–1,1 мс; абзац на 150 знаків — 27 мс, 300 — 176 мс, 600 — 1,32 с (кубічне зростання).
- У продакшні (читання, без користувачів 5 і 967): 2014 — 3324 персонажі, найдовший абзац 4855
  знаків (передісторія), 55 персонажів мають абзац понад 600 знаків, 14 — понад 1500. «Лист 2024»
  доступний для будь-якої редакції, а PDF генерується в server action без воркера, тож один друк міг
  заблокувати сервер на хвилини чи години.

## Рішення

- Спільний модуль `src/server/pdf/textFit.ts` (перенесено з `sheet2024/textFit.ts`): перенос як у
  pdf-lib, але лінійний — кожне слово міряється один раз при кеглі 1, готовий рядок перевіряється
  одним справжнім виміром. Кегль шукається двійковим пошуком. Останній рядок має вмістити
  виносні елементи літер. Слово, ширше за рядок, ділиться по літерах.
- Багаторядкові поля отримують уже розбитий текст (рядки через `\n`), тож pdf-lib лише малює.
  Тому в редагованому PDF у таких полях стоять жорсткі розриви рядків.
- `splitTextToFit` повертає рядки, що влізли, і залишок тексту; `textFlow.splitFlowLines` повертає
  `rest` замість мовчазного відкидання (2024 його поки не використовує).
- Класичний аркуш: блок володінь компактний — «Мови: …» першим рядком, далі чуття й опори одним
  рядком, далі «Обладунки / Зброя / Інструменти / Інше» по рядку (той самий текст іде в поле
  «Володіння інструментами та мовами» листа 2024).
- `src/server/pdf/printContinuation.ts`: поле сторінки 1 дрібнішає лише до 6 pt; решта тексту
  продовжується в полі «Уміння та Особливості» з позначкою «… далі в «Уміння та Особливості»», поки
  це поле саме лишається не дрібнішим за 6 pt. Якщо місця немає — поле дрібнішає до 4,5 pt і
  закінчується «… далі не вмістилося», а не мовчазним обрізанням. Нова сторінка ніколи не додається.
- Поля шапки — один рядок зі зменшенням; два рядки лише коли один став би дрібнішим за 6 pt.

## Журнал

- 2026-10-16: перенос і підбір кегля спільні й лінійні; лист 2024 для того самого друїда — 0,3 с
  замість 206,7 с, PNG піксель у піксель збігаються з попередніми. Стрес: чотири абзаци по ~6000
  знаків — класичний 1,0 с, лист 2024 2,3 с. Класична сторінка 1: мови першим рядком, продовження
  в «Уміння та Особливості», шапка в один рядок. Тести: `tests/logic/pdf-text-fit.test.ts`,
  `src/server/pdf/proficiencyLanguageText.test.ts`, `tests/pdf/*`.
- Не зроблено: продовження на сторінку деталей (порожні поля бланка `CharacterDetails.pdf`) і в
  вільні поля листа 2024; запобіжник на час генерації (воркер або тайм-аут) — після лінійного
  переносу найгірший відомий випадок займає секунди, але генерація досі йде в процесі сервера.
