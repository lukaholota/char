## Мета

Закрити чергу, яку aidedd закрити не міг. `magic-items-manifest.json` тримав **191** рядок зі
статусом `deferred` — усі з позначкою «тільки резюме (не OGL)»: рядок типу на сторінці був, а
тексту правил не було. Це п'ята частина каталогу предметів, і всі 191 лишалися або порожніми,
або зі старим перекладом, якого ніхто не звіряв із книгою.

**Це закриває O14:** відкладених предметів не лишається.

## Перше рішення: предмети йдуть у базу, не в JSON

[Р15](../DECISIONS.md#р15) тримає **істот** у JSON, і конвеєр KR16.3 нікуди, крім `data/` і
`src/lib/generated/`, не пише. Предмети влаштовані інакше й до цього KR: `magicItems.json`
**будується з бази** (`scripts/generate-magic-items.ts`), а текст їде туди сідом
(`prisma/seed/magicItemSeed.ts`). Тобто копіювати конвеєр бестіарію один-в-один було не можна —
файл перекладу нікуди б не доїхав.

Тому KR16.4 **не заводить власного сховища**, а продовжує конвеєр O14: партії лягають у
`prisma/seed/magic-items/batch-NN.json` (11–18) поруч із десятьма партіями aidedd, той самий
сідер накладає їх на `baseline.json` за `engName`, і той самий `seed:magic-items:*` кладе
результат у базу. Нового немає нічого, крім робочої зони перекладу й планувальника.

```
маніфест (191 deferred)
  → plan:items            → data/5etools/item-batches.json      ← пінує книгу й id
  → scan:item-batch       → брифінг перекладачеві (stdout)
  → переклад              → data/5etools/translations/magic-items-2014/batch-NN.json
  → build:item-batch      → prisma/seed/magic-items/batch-NN.json    ← контракт, комітиться
  → seed:magic-items:test → spells_test
  → seed:magic-items:prod → production                                ← ВЛАСНИК, не агент
  → generate:magic-items  → src/lib/generated/magicItems.json
```

Межа та сама, що в O14: `data/**` — робоча зона, `prisma/seed/**` — контракт. Контракт руками
не редагують; правлять переклад і пересобирають.

## Читач джерела: `scripts/5etools/source-item.ts`

Це не `ParsedMagicItem` з aidedd. Там рядок типу друкований, і його розбирали регуляркою; тут
тип, рідкість і налаштування лежать окремими полями, тож рядок типу навпаки **збирається** —
щоб перекладач бачив те саме, що надруковано в книзі.

Що довелося вивести, а не вгадати:

- **Тип.** Коди 5etools (`M`, `R`, `S`, `LA`/`MA`/`HA`, `RG`, `RD`, `WD`, `ST`, `P`, `SC`,
  `INS`, `SCF`, `A`/`AF`) виведено з `Parser.ITEM_TYPE_JSON_TO_ABV` пінованої ревізії. Невідомий
  код — помилка, не відкат на «дивовижний предмет».
- **Тип варіанта.** `magicvariants.json` власного типу не має — має `requires` із переліком
  базових предметів. `{"sword": true}` дає зброю, `{"type": "HA"}` — обладунок,
  `{"name": "Pike"}` (`Dragonlance`) і `{"weaponCategory": "martial"}` — теж зброю. Мовчазний
  відкат тут заборонений: `Dragonlance` поїхала б у каталог дивовижним предметом і зникла б
  із фільтра зброї.
- **Підстановки.** `{=bonusWeapon}` і `{=bonusWeaponDamage}` розкладаються з полів самого
  запису. Без них у тексті лишалося б «you gain a {=bonusWeapon} bonus».
- **`attachedSpells`** буває і масивом, і об'єктом за частотою (`{daily: {"1e": […]}}`), і в
  другій формі несе ключ `ability` — характеристику, а не заклинання. Без винятку «int»
  доїжджав у перелік як назва заклинання.
- **`rarity: "varies"`** віддається як `null`, а не гаситься мовчки: такий рядок мусить узяти
  рідкість із плану разом із причиною, інакше збірка падає.
- **Проза** рендериться в той самий Markdown, що вже лежить у каталозі: абзаци через порожній
  рядок, підпункти жирним, таблиці рядками `| … |`. Невідомий вузол — помилка.

## Гейт: `tests/content/5etools-magic-items.test.ts`

**19 перевірок, кожна доведена червоною мутацією.** Гейт дивиться на **зібрану сід-партію**, а
не на файл перекладу: між ними стоїть збирач, і саме там переклад зустрічається з машинними
полями. Перевірка на вході сказала б лише те, що написав перекладач, а не те, що доїде в базу.

| Мутація | Що впало |
|---|---|
| з плану прибрано рядок | покриття маніфесту (+ каскад: покриття сід-партій) |
| `magicItemId` 1006 → 9006 | id каталогу незмінний |
| `revision` → `main` | пінована ревізія |
| пінована книга `XGE` → `XDMG` | пінування одного запису корпусу (+ каскад збірки) |
| `status: blocked-term` без blocker-а | blocker названо (+ каскад) |
| прибрано `rarityReason` | рідкість плану має причину (+ каскад) |
| `isNewToCatalog` перевернуто | збіг із базовим корпусом |
| з партії перекладу зник рядок | кожен готовий рядок має переклад (+ каскад) |
| з назви прибрано `[English]` | формат назви (+ каскад KR14.1) |
| маркер Р20 у `shortDescription` | маркери лише в описі |
| маркер назвав `{{Sigil}}` замість `{{Mechanus}}` | маркер називає рядок джерела |
| «не забруднюється» → «не gets dirty» | латиниця |
| «600 фт» → «300 фт» | числа проти джерела |
| «дію» → «урон» | ратифікована термінологія 2014 |
| «Розвіювання магії» → «Розсіювання магії» | ратифікована форма назви заклинання |
| порожній `shortDescription` | підпис і опис непорожні |
| `itemType` збирача підмінено на `WEAPON` | машинні поля з джерела |
| налаштування збирача інвертовано | шість правок П11 O14 |
| `varies` тихо стає `COMMON` | збірка падає названою помилкою |
| зайвий новий предмет у контракті | каталог росте лише на дозволене (+ каскад) |
| `stripGlossaryMarkers` прибрано з `seo-utils` | SEO-опис без сирих маркерів |

Після кожної мутації файл відкочувався, **md5 усіх 21 файла даних і скриптів збігся** з
домутаційним.

**Каскади названі каскадами.** Збірка (`readBuilt()`) падає на дефекті плану — не тій книзі,
рідкості без причини, — і тягне за собою всі перевірки, що на неї спираються. Щоб це не
забирало **весь** файл разом із тими перевірками плану, які цей дефект і називають, збірка в
гейті **лінива**: спершу відпрацьовують сім перевірок плану, і лише потім будується контракт.

## Що знайшлося дорогою

**`Perfume of Bwitching` — це `Perfume of Bewitching`, який уже стоїть у каталозі.** Маніфест
збирався додати дубль наявного предмета під новим id 1303. Спіймала перевірка
«`isNewToCatalog` збігається з базовим корпусом», а не вичитка. Планувальник тепер бере id
каталогу, щойно виправлена назва там знаходиться. Подробиці —
[питання 48](questions.md#48-perfume-of-bwitching-маніфесту--це-perfume-of-bewitching-каталогу).

**19 назв заклинань стояли не в ратифікованій формі.** «Велике відновлення» замість «Більше
відновлення», «Оживлення» замість «Відродження», «Пристріт» замість «Проклін», «Свобода руху»
замість «Свобода рухів», плюс відмінкові форми («Розмову з мертвими» замість «Розмова з
мертвими»). Жодну з них не бачив ні гейт, ні око — знайшла окрема звірка проти
`dictionary.json → SPELLS`, яка після цього стала **перевіркою гейта**: назва або стоїть рівно
так, як її ратифіковано, або вона взагалі не заклинання — і тоді названа поіменно з тим,
звідки вона (риса класу, статблок, предмет каталогу, незакомічений KR17.3).

**`<meta name="description">` віддавав сирі `{{Mechanus}}`.** SEO-опис збирається
`getDescriptionSnippet` → `stripMarkdown`, повз `FormattedDescription`, тобто повз розгортання
маркера. Це стосується **всіх** сторінок сутностей, не лише предметів: бестіарій із маркерами
Р20 віддавав те саме. Полагоджено там, де визначення одне, — `stripMarkdown` тепер знімає
маркери тим самим `stripGlossaryMarkers`, який читає рендерер.

**«Годинникова накидка» для `Cloak of Billowing`.** Успадкована назва плутала `billowing`
(розвіватися) з `clockwork`. Партія 11 переписала на «Плащ розвівання».

**Чотири машинні поля розійшлися з джерелом — рівно ті п'ять, що обіцяло питання 11 O14.**
Жодного зайвого: `Boots of False Tracks` і `Prosthetic Limb` перестали потребувати
налаштування, `Instrument of Illusions`, `Instrument of Scribing` і `Nature's Mantle` почали.
`Ersatz Eye` не зрушив — там помилялося саме aidedd, і гейт це тепер стереже поіменно.
Типів і рідкостей із джерелом не розійшлося **жодного**.
