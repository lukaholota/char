# KR36.1 — Один реєстр каталогів

**Ціль:** [O36](README.md) · **Статус:** 🟢 зроблено 2026-09-18 · **Залежить від:** нічого

## Що робимо

Замість пʼяти паралельних списків — один реєстр каталогу платформи, з якого читають усі
споживачі. Форма вже є: `HOME_CATEGORY_MANIFEST` у
[`homeCategories.ts`](../../src/components/home/homeCategories.ts) тримає `slug`, підпис, шлях 2014
і `editions`, а шлях 2024 виводить. Реєстр — це той самий манифест, доповнений полями, яких він
не знає, і піднятий із теки `components/home/` туди, де його може читати і пошук.

| Поле | Звідки зараз | Навіщо |
|---|---|---|
| `slug` / категорія | `homeCategories.ts` + `OmniSearchCategory` | один ключ на каталог замість двох просторів |
| підпис (і `title2024`) | тричі: манифест, `OMNI_CATEGORY_LABELS`, `NavExtraMenu` | «Раси» / «Види», «Вливання Винахідника» |
| шлях 2014 + `editions` | лише манифест | інфузії — лише 2014, бастіони — лише 2024 |
| іконка / акцент / обкладинка | манифест і `searchVisuals.ts` | без змін, просто в одному місці |
| колектор індексу | `buildOmniSearchIndex` | категорія без колектора — дефект, а не порожнеча |
| порядок у вікні пошуку | `CATALOG_ORDER` | лишається окремим полем: у пошуку свій порядок |
| чи є таб фільтра | `FILTER_TABS` | лишається полем: 16 табів у рядок не влазять |

Споживачі після правки: плитки головної, `NavExtraMenu`, `omni-categories.ts`,
`OmniSearchCategoryLinks`, `OmniSearchPanel`, `sitemap.ts` (`CATALOG_INDEX_PATHS` — шоста копія
списку: інфузії там дописані окремим рядком поза циклом редакцій, бо цикл не знає про каталог
однієї редакції).

Адресу каталогу реєстр віддає **за редакцією**, а не конкатенацією префікса: `findCategoryCatalogHref`
зараз віддає мертвий `/bastions` для 2014. Каталог, якого в цій редакції немає, не має віддавати
адресу взагалі — ні плиткою, ні табом, ні посиланням із результату.

## Готово, коли

- [ ] реєстр каталогів живе в одному модулі й не імпортує каталожних JSON (інакше повернеться
      дефект №9 зі [STATE.md](../STATE.md) — компонент, якому треба підпис, тягне 7,5 МБ індексу);
- [ ] плитки головної, меню, плитки й таби пошуку, категорії індексу і `sitemap.ts` читають його,
      а не власну копію;
- [ ] `findCategoryCatalogHref` для каталогу поза редакцією не віддає адреси;
- [ ] гейт `tests/content/catalog-registry.test.ts`: кожен запис реєстру має маршрут на диску,
      підпис, дозволені редакції й або колектор індексу, або явну позначку «пошук серверний»
      (`characters`); кожен маршрут каталогу в `src/app/` присутній у реєстрі;
- [ ] гейт бачено червоним: додати каталог у реєстр без колектора, прибрати таб у наявного,
      підмінити `editions` — і кожна з трьох правок валить гейт окремо;
- [ ] `tests/content/omni-search.test.ts` більше не перелічує категорії руками, а бере їх із
      реєстру (і його назва перестає брехати про «10 categories»).

## Чому не «просто дописати бастіони й інфузії»

Проводка каталогу — шість місць, і остання ([KR35.4](../o35-metamagic-catalog/kr35.4-metamagic-catalog-pages.md))
пройшла по всіх шести руками, бо нічого не змушує. Метамагії пощастило, інфузіям — ні: вони
доїхали до головної, меню й sitemap, але не до пошуку, і це протримало їх невидимими для `Cmd+K`
від KR9.2 до сьогодні.

## Зроблено 2026-09-18

Реєстр — `src/lib/catalogs/catalog-registry.ts`: 16 записів, поля `slug`, `title` / `title2024` /
`homeTitle` / `searchTitle`, `path` (2014), `editions`, `home` (ярус, акцент, обкладинка без ШІ),
`menuIcon` (`null` — каталог у головній панелі), `search: "index" | "server"`, `searchOrder`,
`isPublic` (sitemap). Жодного імпорту каталожних даних. `omni-categories.ts` видалено;
`homeCategories.ts` став тонким читачем реєстру (API `collectHomeCategories` збережено).

Читають реєстр: плитки головної, `NavExtraMenu` (порядок пунктів тепер = порядок плиток
головної; підпис «… 2024» виводиться правилом, а не пишеться), плитки й таби вікна пошуку
(таби — усі каталоги редакції в `searchOrder`; рядок табів прокручується), колектори індексу,
`sitemap.ts` (корені каталогів — з реєстру, окремі рядки «/infusions», «/2024/bastions»,
«/rules» зникли).

`findCatalogHref(slug, edition)` віддає `null` поза редакцією; споживачі не малюють плитку і не
ведуть посилання. `findRoutePrefix` і `toEdition` живуть тут же.

На кожен каталог редакції індекс тримає один рядок «Каталог» (`id: category-<slug>`,
`isCatalogShortcut`): аліаси каталогу — у `search-aliases.json` під `entityType: "catalog"`
(туди ж переїхали «бекграунд», «передісторія», «історія» з константи в коді). Гейти, що
рахують записи категорії, виключають цей рядок.

Гейт `tests/content/catalog-registry.test.ts` (12 перевірок): унікальність слагів і порядку;
кожна адреса має `page.tsx` на диску, поза редакцією — `null`; кожен маршрут `src/app` і
`src/app/2024` з `page.tsx` є в реєстрі (службові — у явному списку); каталог `index` має
рядки рівно у своїх редакціях, `server` — жодних; рядок «Каталог» — рівно один на каталог
редакції; реєстр не імпортує `*Data`/`generated`; шість колишніх власників списку імпортують
реєстр; плитки, меню (+ головна панель), таби дають один набір; sitemap несе корені публічних
каталогів і не несе персонажів, хоумбрю та каталог поза редакцією. `omni-search.test.ts`
перелічує категорії з реєстру.

Бачено червоним (кожна правка окремо, файл відновлено з копії): `editions` бастіонів → обидві
(4 падіння), колектор інфузій знято з індексу (1), `findCatalogHref` без `null` поза редакцією
(2).
