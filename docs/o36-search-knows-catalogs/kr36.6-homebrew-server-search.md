# KR36.6 — Хоумбрю спільноти в пошуку (серверна фаза)

**Ціль:** [O36](README.md) · **Статус:** 🟢 зроблено 2026-09-18 · **Залежить від:** [KR36.1](kr36.1-catalog-registry.md)

## Звідки

Питання 2 в [questions.md](questions.md): каталог живе в базі, тож у статичному індексі його
рядків бути не може. Рекомендація була «backlog до релізу 2024» (один живий запис у робочій
базі). Власник 2026-09-18: «давай одразу закладемо» — тому KR, а не backlog.

## Що зроблено

- `src/server/db/homebrew-search-actions.ts` — серверна дія `searchHomebrewEntries(query, ruleset)`
  за зразком пошуку персонажів (Р14): підрядок по назві з варіантами г↔х із `buildQueryVariants`,
  `deleted_at is null`, запис редакції або без редакції, до 8 рядків за рейтингом. Без власника —
  каталог публічний. Адреса — сторінка запису `/homebrew/<id>` (`?edition=2024` у 2024).
- У реєстрі каталог позначено `search: "server"`: гейт реєстру вимагає, щоб в індексі **не було**
  його рядків, і водночас дає йому плитку й таб.
- Панель тримає обидві серверні фази одним гуком `useDeferredServerSearch` (затримка 200 мс,
  скасування застарілого запиту, помилка → порожньо), замість двох однакових `useEffect`.
- Іконка категорії — колба (`FlaskConical`), як у меню.

## Гейт

`tests/db/homebrew-search.test.ts` (інтеграційний, `bun run test:integration`): знаходить за
назвою і з г↔х, не показує видалених, запис 2024 видно лише в 2024, запис без редакції — в обох,
короткий запит не йде в базу.

## Чого нема

Пошук лише по назві. Шукати по тексту опису (заклинання, статблок) — коли записів стане
більше, ніж один; тоді ж і повнотекстовий індекс у Postgres.
