# KR20.2 — Переклад SRD 5.1 українською

**Ціль:** [O20](README.md) · **Статус:** ✅ закрито 2026-08-29 · **Залежить від:**
[KR20.1](kr20.1-parser-2014.md)

## Мета

Перекласти 42 статті / 101 підрозділ / **36 311 слів** SRD 5.1 так, щоб довідник 2014 говорив
тією самою мовою, що й риси, заклинання й стани, які вже в базі. Обсяг — приблизно як весь
2024-корпус разом узятий, тому робота йде партіями й **термінологія узгоджується до першої
партії, а не всередині неї**.

## Формат — той самий, що для 2024

Переклади лежать у `data/2014/rules-uk/batch-NN.json` і **комітяться** (це людський продукт;
генератор їх лише зшиває, тож перегенерація ніколи не втрачає перекладу). Форма файлу — точно як
у [data/2024/rules-uk/](../../data/2024/rules-uk/):

```json
{
  "<article.id>": {
    "title": "Порядок бою",
    "summary": "Одне-два речення, які побачить пошук і картка статті.",
    "tags": ["ініціатива", "раунд", "хід"],
    "subsections": {
      "<subsection.id>": { "title": "…", "content": "…markdown…" }
    }
  }
}
```

`id` статей і підрозділів бери **з прогону генератора**, не вигадуй: `npx tsx -e` над
`buildRuleArticles2014()` або з `src/lib/generated/rules-2014.json` після
`bun run generate:rules-2014`.

## Крок 1 — термінологічний прохід (робиться один раз, окремим запуском)

Це найдешевший спосіб не переписувати потім 14 партій.

1. **Виклич скіл `dnd-ua-translation` через Skill**, не читай його SKILL.md як файл — читання
   пропускає гейт узгодження термінів.
2. Витягни з англійського корпусу всі терміни правил, які трапляються ≥ 2 разів
   (дії, стани, типи перевірок, терміни бою, відпочинку, руху, приховування, укриття).
3. Кожен звір із [dictionary.json](../../src/lib/refs/dictionary.json) **грепом**, а не пам'яттю.
   Термін, який там уже є, — ратифікований, його не обговорюють і не «покращують».
4. Звір із **фактичним ужитком**: `prisma/seed/**`, `data/2014/**`, `src/lib/rulesData.ts`
   (34 статті + 16 станів уже українською). Якщо словник і ужиток розходяться — це знахідка для
   власника, а не привід вибрати самому.
5. Те, чого немає ніде, випиши в [unknown-terms-rules-2014.md](unknown-terms-rules-2014.md) з
   варіантами й рекомендацією — по одному рядку на термін. Це файл для власника; **партії не
   стартують, поки він не відповів.**
6. Нові ратифіковані терміни вносиш у `src/lib/refs/translation.ts` і дзеркалиш
   `npx tsx scripts/sync-dictionary-from-translation.ts`.

**Одностайність корпусу не є аргументом.** Якщо 20 файлів вживають термін однаково, це вимірює
поширення варіанта, а не його правильність — рішення все одно за словником і за власником.

### Правила всередині партії

- **Скіл `dnd-ua-translation` — обов'язково, через Skill.**
- **У словник партія не пише.** Новий термін → рядок у `unknown-terms-rules-2014.md`, у тексті
  тимчасово залишається найкращий варіант із маркером. Так тримається паралельність.
- **Неоднозначний термін несе оригінал** — `променевої{{radiant}}`, [Р20](../DECISIONS.md#р20).
  Тільки в прозі. Визначення одне — `src/lib/refs/glossary-marker.ts`, свого не заводити.
  Ратифікація маркера не знімає (уточнення власника 2026-09-02, [Р20](../DECISIONS.md#р20)).
- **Markdown зберігається**: таблиці, списки, жирний. Маркер `{{…}}` не знає ні про `- ` списку,
  ні про `**` жирного — перевір, що розмітка не з'їдена (цю пастку вже ловили в
  [KR19.1](../o19-bastions/kr19.1-facility-catalog.md)).
- **Числа, кубики, DC, футові відстані не перекладаються й не перераховуються.** `1d4`, `DC 15`,
  `30 футів` — як у джерелі.
- **Ніяких вигаданих правил.** Якщо абзац незрозумілий — перекладай дослівно й познач рядком у
  `questions.md`, а не переказуй своїми словами.

## Стани — окремий випадок, прочитай перед партією 14

16 станів уже українською в `CONDITIONS_DATA` (`src/lib/rulesData.ts`) і вжиті в риса́х,
підкласах і бестіарії. Переклад `Conditions.md` **зобов'язаний збігтися з ними слово в слово**;
якщо збіг неможливий — це не переклад, це розбіжність, і вона йде власнику. Що робити з
дублюванням «стан у `CONDITIONS_DATA` + стаття зі SRD» вирішує
[KR20.4](kr20.4-merge-handwritten.md), не ця партія.

## Журнал

_Черга партій. Перед стартом додай рядок «партія NN — взято, сесія від DD.MM» і онови його на
«закрито» після коміту._

### 2026-08-29 — зроблено

**Термінологічного проходу з довгим списком не знадобилося, і це вимірюваний факт.** Зі 185
заголовків 2014-корпусу **80 уже мали готовий український відповідник** у перекладеному
2024-корпусі (`Difficult Terrain` → Важкопрохідна місцевість, `Cover` → Укриття, усі стани,
усі дії). Решта — або очевидні («Time» → «Час»), або вже вжиті в рукописних статтях 2014
(«Темп подорожей», «Кров асасина», «Поріг шкоди»). Тому окремий файл
`unknown-terms-rules-2014.md` не заводився: власникові пішло рівно одне питання — пантеони.

**Рішення власника 2026-08-29: пантеони перекладаємо, імена транслітеруємо з оригіналом.**
Усталені в українській традиції (Зевс, Одін, Ісіда, Анубіс, Тор) пишуться традиційно й без
маркера; менш відомі несуть його — `Морріган{{Morrigan}}`, `Ґойбніу{{Goibhniu}}`,
`Ньйорд{{Njord}}`. Питання 3 в [questions.md](questions.md) закрите цією відповіддю.

**СЛ, а не СК.** Це головна редакційна пастка партій: 2024-корпус усталив `Складність Кидка (СК)`,
а рукописні статті 2014 — `СЛ`. Обидві редакції живуть на одному сайті, тож 2014-переклад
тримає **СЛ**, і тест окремо стежить, щоб «зі СК 15» не з'явилося в 2014-корпусі.

**20 партій замість запланованих 14** — `data/2014/rules-uk/batch-01.json` … `batch-20.json`.
Розбиття пішло не за розміром файлів, а за смисловими блоками: спершу бойові статті (те, чого
власник не знаходив у пошуку), тоді характеристики, чарування, стани, пригоди, а наприкінці —
матеріал Майстра. Найбільші партії: «Атака» (3 580 слів), пастки (2 994), перевірки характеристик
(4 056).

**Назви взято з реєстрів, не з голови.** Заклинання — з `SPELLS` (499 записів): _Прогулянка з
вітром [Wind Walk]_, _Наділити прокляттям [Bestow Curse]_, _Планарний перехід [Plane Shift]_.
Предмети — з `magicItems.json`: _Черевики кроку й стрибка_, _Килим-літак_, _Перстень захисту_.
Істоти — з `creatures.json`: Отиуг, Пурпуровий хробак, Падальний повзун. Домени кліриків — з
`subclassTranslations`. Двічі це виправило вже написаний текст: «Килим-літун» → «Килим-літак»,
«Ідентифікація» → «Розпізнавання».

**Гейт доведено червоним:** прибрати `batch-09.json` (стани) — падає три твердження, зокрема
звірка з `CONDITIONS_DATA`; повернути — зелено. `bunx tsc --noEmit` чисто, `bun run lint`
0 errors, `bun run test` — **1 335 зелених**. Три червоних — ті самі чужі тести заклинань
(`ratified-spell-names`, `extended-spell-lists-2014`, `catalogs-2024`), що падали до початку
роботи над O20.
