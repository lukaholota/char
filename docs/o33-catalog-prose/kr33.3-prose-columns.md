# KR33.3 — Носій прози: колонки опису в `class`, `race`, `subrace`

**Ціль:** [O33](README.md) · **Статус:** ✅ закрито 2026-09-13 · **Блокує:** KR33.4, KR33.6, KR33.7 ·
**Спирається на:** [Р2](../DECISIONS.md#р2) (база — джерело істини, міграцій немає)

## Що не так

Проза класу й раси не «загубилася при імпорті» — **її ніде тримати**. `prisma/schema.prisma`:

- `model Class` — 34 поля, жодного текстового опису;
- `model Race` — те саме;
- `model Subrace` — те саме;
- `model Subclass` — `description` є;
- `model Creature` — `description` є.

Через це переклад видів 2024, зроблений ще на імпорті O6, лежить у
`data/2024/normalized/species.json` мертвим вантажем: 10 із 10 описів українською, і жоден із них
не має куди поїхати.

## Що робимо

Один DDL-файл на всю ціль — [`db/changes/2026-09-13-kr33.3-catalog-prose.sql`](../../db/changes/2026-09-13-kr33.3-catalog-prose.sql):

```sql
ALTER TABLE "class"   ADD COLUMN IF NOT EXISTS "description" text;
ALTER TABLE "race"    ADD COLUMN IF NOT EXISTS "description" text;
ALTER TABLE "subrace" ADD COLUMN IF NOT EXISTS "description" text;
```

Другої колонки під коротку форму **не буде**: власник 2026-09-09 обрав коротку прозу як єдину
(≈ 145 слів, два–три абзаци), тож `description` і є та коротка форма. `shortDescription` видів
2024, який лежить у `species.json`, у базу не їде — див. [KR33.4](kr33.4-prose-2024.md).

Варіанти рас (`race_variant`) у цьому KR не чіпаємо: у книзі варіант — це не окрема стаття з
прозою, а модифікація раси. Якщо KR33.6 знайде для них текст у джерелі — колонка додається там.

Далі за конвенцією схеми:

1. власник застосовує SQL до робочої бази;
2. агент застосовує той самий файл до `spells_test` через `./scripts/apply-db-change.sh`
   (**чистий diff схеми не доводить, що зміна є в клоні** — перевіряти сам клон);
3. `bun run db:pull` — `schema.prisma`, клієнт і `db/schema.sql` одним кроком;
4. `generate:classes` і `generate:races` віддають нове поле в `classes.json` / `races.json`;
5. картки класу й раси малюють прозу під шапкою — **тільки коли вона є**.

## Порожня колонка не повинна нічого малювати

До KR33.4 колонки порожні в обох базах. Умова «є текст — малюємо блок, немає — картка як була»
має бути в рендері з першого дня, інакше після DDL прод дістане порожню рамку.

Окремо: `null` — це відсутність опису, а порожній рядок `""` — теж. Чистити колонку треба
`Prisma.DbNull`, а не `JsonNull` — це текстова колонка, тож пастка не та сама, але правило
«порожнє значення має бути одне» лишається: пишемо `null`, не `""`.
