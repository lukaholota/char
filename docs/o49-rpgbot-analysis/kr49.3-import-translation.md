# KR49.3 — Повний імпорт і український переклад аналітики

**Стан:** 🟡 триває; власник доручив повний crawl включених URL 2026-09-29.
**Залежності:** KR49.1–49.2. **Результат:** повні source revisions та reviewed переклади
всіх included матеріалів, не добірка скорочених гайдів.

## Перед перекладом і публікацією

Власник прямо доручив зібрати повні HTML включених статей. `crawl-sources.py` читає
лише manifest included, перевіряє `robots.txt`, обмежує частоту, звіряє canonical URL,
пише незмінні source-файли та відновлюваний журнал. `stage-sources.ts` витягає AST
через preview/apply, не публікує англомовні тексти. Власник відклав 63 manifest review
до повного приймання. Рішення щодо використання перекладів у публічному продукті
відокремлене від технічного збирання джерела.

Перед першою партією прочитати й застосувати
[`dnd-ua-translation`](../../.agents/skills/dnd-ua-translation/SKILL.md), словник і
`translation.ts`, [процедуру контенту](../WORKFLOWS.md#content-and-translations).
Для нових D&D-термінів виконати gate погодження до batch. Нові оцінки не створюються.

## Конвеєр

1. Зберегти повну ревізію джерела з авторами, canonical URL, датами й hash.
   Із HTML прибрати навігацію, рекламу й коментарі; зберегти всі аналітичні блоки.
2. Нормалізувати content AST, source anchors і ratings. Відмінності markup у старих
   та нових статтях, inline styles, conditional ratings і таблиці мають явний fallback
   у звіт. Невідомий блок не зникає мовчки.
3. Пілот: 10–12 повних матеріалів, що охоплюють обидві редакції, класовий guide,
   comparison guide, dedicated subclass, расу/гілку, рису, заклинання, предмети,
   мультиклас і складну таблицю. Якщо тема вкладена, перевірити весь її розділ.
4. Перекласти весь текст зі збереженням тональності, авторських висновків, умов,
   пояснень оцінок, чисел і прикладів. Посилання на наші сутності звіряти за редакцією.
   Помилку автора за потреби позначити редакторською приміткою, не міняти непомітно.
5. Виміряти пілот: слова за типом статті, час перекладу/перевірки, дефекти extraction.
   Оновити бюджет і розбити весь manifest на контрольовані партії з coverage ledger.
6. Звірити й перевести кожну партію в reviewed/published. Source update позначає
   переклад stale; rerun не перезаписує відредагований український текст.

## Повторний запуск і файли

З кореня репозиторію, із мережевим доступом для першої команди:

```sh
python3 scripts/rpgbot/crawl-sources.py
bun scripts/rpgbot/stage-sources.ts
bun scripts/rpgbot/stage-sources.ts --apply
bun scripts/rpgbot/reextract-corrections.ts
bun scripts/rpgbot/reextract-corrections.ts --apply
bun scripts/rpgbot/coverage.ts --apply
```

Перший крок відновлюється з `data/rpgbot/source-crawl.json`, пропускає вже перевірені
source IDs і зупиняється на HTTP 429. Для вибірки є `--limit N`; `--refresh` навмисно
запитує всі included URL заново, зберігаючи старі HTML-ревізії. Другий крок — тільки
preview. `--apply` додає відсутні source/staging-файли, не перезаписує наявні ревізії.
Останній крок оновлює `data/rpgbot/translation.coverage.json`: 417 publication slots
на 415 included source IDs, бо дві статті належать обом редакціям. Рядки `review`
manifest не маскуються як imported і не входять до цих 417 слотів.
Корекції витягу зберігаються окремо від початкового staging; preview показує
лише сторінки, де новий extractor прибрав `text-coverage-review`. Перед `--apply`
потрібно перевірити зміни коду й тести. [Формат накладок](../../data/rpgbot/staging-corrections/README.md).

## Структура довгих текстів

Оригінал RPGbot часто пише пункт оцінки суцільною стіною тексту. Для читача чернетки
(рішення власника 2026-10-01) український текст ділимо на абзаци, навіть якщо в оригіналі
їх не було:

- порожній рядок усередині поля «Українською» аркуша — розрив абзацу, один перенос рядка —
  перенос усередині абзацу; компілятор зберігає їх у text-вузлі, читалка малює проміжок
  (`InlineContent`, `splitLineBreaks`);
- нові переклади одразу пишемо з абзацами: вердикт і мотив — перший абзац, далі кожна окрема
  думка, застереження чи приклад. Заголовок пункту з маркером лишається в першому абзаці;
- уже готові аркуші ділить `scripts/rpgbot/paragraphize.py` (довгі фрагменти від 420 знаків,
  межі речень, абзац близько 130–320 знаків, новий абзац перед «Проте», «Однак», «Також» тощо;
  посилання, маркери `{{…}}`, лапки й дужки не розрізає). `--apply` змінює аркуш, чернетку
  потім перезбирають командою компіляції. Скрипт не чіпає фрагмент, що вже має переноси.
  Розбиття механічне: довгі пункти варто вичитувати й за потреби правити вручну.

## Приймання

- [ ] Кожен included source entry має повну перекладену ревізію й статус перевірки.
- [ ] Усі змістовні sections, lists, tables, числові приклади й ratings збережені.
- [ ] Rating context, оригінальний колір і ціль відповідають конкретним source blocks.
- [ ] Автоматичний coverage report виявляє пропущені блоки; редактор звіряє зміст,
  а не лише кількість секцій чи збіг hash.
- [ ] Автори, оригінал і дата звірки відображаються; editorial notes відділені.
- [ ] У translation ledger немає прихованих draft, missing і extraction failures.

Пілот дозволяє починати UI, але **не закриває KR49.3**. Готовність повного корпусу
оцінюється за manifest, не за наявністю 10 красивих сторінок.
