# Взаємна привʼязка сутностей RPGbot — 2026-10-09

## Контракт і архітектура

Обидва напрямки використовують `EntityRef` та `entityIdentity` з `bindings.ts`: `[ruleset, kind, parentKey, entityKey]`. Підкласи каталогу й конструктора мають спільні enum-ключі; ключ здібності формує чинний `findFeatureKey` з англійської ідентичності та рівня. Реєстр `data/rpgbot/bindings.json` привʼязує цей ключ до `articleId`, `sectionId`, точного `optionId` і оцінок. Це відповідність даних, а не окремий UI-код для кожної здібності.

Стаття → правила: `collectArticleFeatureHydration` зіставляє згадки з native catalog, передає повний оригінальний український опис. Native підклас → аналіз: `readSlicePreview` і `FeatureAnalysis` знаходять точний пункт через спільну таблицю. Ідентичність англійської назви наразі є контрактом ключа: перейменування її у native джерелі потребує регенерації й перевірки привʼязок. Переклад української назви більше не керує відповідністю в конструкторі.

Заклинання мають окремий наявний канал `rpgbot-spell-ratings` зі спільним slug англійської назви та контекстом списку заклинача; це не відсутні generic bindings. Повна перевірка всіх цих каналів ще не замінюється результатом нижче.

## Зміни

- У `SubclassInfoModal` використовується той самий `findFeatureKey`, що в native catalog, замість підбору аналізу за українською назвою й рівнем. Регресія змінює лише українську назву та перевіряє, що кнопка лишається.
- Гідрація й collector зворотних аналізів використовують `resolvePrimaryBinding`. Другорядна привʼязка без основної або дві конфліктні основні не створюють кнопку/аналіз.
- Генератор окремих гайдів зіставляє лише один точний native підклас у темах статті та один розділ `features`. Точна англійська назва має відповідати єдиній native здібності. Чинні primary bindings збережені; неоднозначні збіги не приймаються.
- Додано 6 привʼязок: 1 для Tools of the Trade (Armorer), 1 підклас Володар звірів і 4 його здібності з dedicated guide. Рівні та exact option IDs перевірені; повні правила не замінені аналізом.

Потрібне подальше розділення за типом і сценарієм. 569 unmatched comparison options і 524 unmatched dedicated options включають вкладені компоненти, рівневі списки заклинань, рекомендації й справжні пропуски; їх не можна автоматично ототожнювати з відсутніми native здібностями.

Повного зворотного звʼязку всіх рас/рис/передісторій/предметів цей зріз не доводить. Генеричний native preview API та UI наразі орієнтовані на підкласи. Для інших сутностей потрібне завершення того самого контракту, а не нові per-entity UI винятки.

Без SQL, сідів БД, push або deploy. 2024 не розширено. clean-code-guard: clean — повторно використаний чинний resolver і ключі, нових залежностей немає.
