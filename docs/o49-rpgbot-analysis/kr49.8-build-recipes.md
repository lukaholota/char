# KR49.8 — Структуровані RPGbot-білди й запропоновані варіанти

**Стан:** 🟡 приватний пілот Монаха реалізовано 2026-10-03; KR відкритий. **Залежності:** KR49.2 та source corpus/контентний пілот KR49.3.
Tooling можливий на власних fixtures. **Результат:** перевірені BuildRecipe та
recommendation groups із прив’язками до джерела й сутностей, придатні для складання.

## Реалізація

1. Доповнити manifest ledger усіма example builds і змістовними рекомендаціями
   включених статей. Для кожного — source revision/section, редакція й disposition.
   Не видавати довільну комбінацію кольорових опцій за готовий авторський білд.
2. Реалізувати build/choice/progression контракт з [architecture.md](architecture.md).
   Структурувати стартовий клас, підклас, расу/підрасу, походження, характеристики,
   навички/мови, риси/ASI, заклинання, спорядження та мультикласовий порядок за рівнями.
3. У recommendation groups зберегти source-backed alternatives, оцінки й умови;
   unspecified вибори лишити відкритими. Контекст одного класу не переносити в інший.
4. Розв’язати keys у сутності правильної редакції. Missing entity або недостатній
   source description отримує явний статус incomplete й конкретний список доповнень.
5. Пілот охоплює обидві редакції, однокласовий і мультикласовий recipe, alternatives,
   future subclass/feat та missing entity. Після пілота обробити весь build ledger.
6. Валідатор визначає executable level range/snapshots за фактично завершеними
   виборами; published article саме по собі не робить recipe executable.

## Приймання

- [ ] Кожен знайдений авторський example build має reviewed recipe або обліковану
  причину неповноти; загальна цифра не виводиться з кількості article URL.
- [ ] Кожна запропонована опція має source ref; власні налаштування гравця відділені.
- [ ] Class level і character level розділені; черговість мультикласу збережена.
- [ ] Стартові й майбутні ASI/риси/заклинання/предмети не змішані.
- [ ] Оновлення source revision позначає recipe для повторної звірки, не змінює
  непомітно вже відкритий BuildDraft.
- [ ] Будь-який executable recipe компілюється у повний перевірений AssemblyPlan
  для заявлених рівнів; unresolved choices видимі й не мають вигаданих defaults.

Перевірки — fixtures для progression, constraints, alternatives, edition mismatch,
unresolved entity та source update. Масова перевірка source mappings обліковується
окремо від 2–3 днів інженерної роботи над tooling.
