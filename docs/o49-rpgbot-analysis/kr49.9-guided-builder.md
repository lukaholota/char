# KR49.9 — Дерево створення персонажа за варіантами RPGbot

**Стан:** 🟡 7 пресетів 2014 / 5 класів, заклинач доданий 2026-10-09; того ж дня до них додано ще 8 стартових пресетів Клірика, Друїда, Чорнокнижника, Чародія, Барда, Винахідника, Паладина й Слідопита (підклас 1-го рівня, вибори раси й заклинання всіх класів, див. журнал); публічний доступ і DB-приймання перевіряються окремо, KR відкритий. **Залежності:** KR49.4–49.5 та пілот KR49.8.
**Результат:** `/optimization/build` і `/2024/optimization/build`, а також CTA зі статей.

## Сценарій

Гравець читає analysis → натискає «Зібрати цей варіант» → бачить початкове дерево
з обраним класом/підкласом або конкретним example build → читає пояснення гілок →
обирає/налаштовує расу, походження, характеристики, риси, заклинання й спорядження →
натискає «Зібрати персонажа». Можливий вхід із меню: клас із зображенням, потім гілки.
Вибір виходить із прочитаного аналізу; збережені пояснення й повернення до статті.

## Реалізація

- Tree view показує source-backed alternatives та залежності. На телефоні —
  вертикальний список/гілки з тим самим станом; не додавати graph library без потреби.
- Стан — BuildDraft зі своєю редакцією/recipe revision. Сторінка відновлює source recipe
  за buildId, а локальну чернетку — після reload. Перегляд не змінює ручний creator draft.
- Біля варіанта — назва, applicable score/context за наявності, пояснення та точний
  перехід у статтю. Гравець може відхилитися від рекомендації на підтриману сутність.
- Зміна класу/підкласу/раси оновлює залежні вибори, не стираючи незалежні поля;
  несумісні рішення отримують конкретне повідомлення й можливість виправити.
- Показати target starting level і план розвитку окремо; підсумок виділяє поточні
  та майбутні придбання, рівні класів і мультикласову черговість.
- Named builds додати до категорії аналітики в пошуку KR49.6 з source/build адресами.
  Не змішувати їх із живими персонажами користувача.
- Ефект складання з початкової ідеї короткий, доступний із reduced motion;
  кнопка веде в KR49.10, не створює DB-запис під час анімації.
