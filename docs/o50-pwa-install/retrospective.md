# O50 — ретроспектива PWA, 2026-10-10

Запит власника: переглянути зроблене як користувацький сценарій, виправити незручності; зокрема, на iPhone у встановленому застосунку бракує браузерної кнопки «Назад».

## Що змінилося після перегляду

### Видиме «Назад»

У standalone перший пункт навігації — «Назад». Телефон зберігає пʼять цілей натискання, «Головна» доступна в меню; на desktop також через логотип. У звичайному браузері панель зберігає «Головна».

Просто `history.length > 1` недостатньо: попередній запис може бути за межами застосунку. Bootstrap до React зберігає індекс власних записів у `history.state`, не стираючи стан Next. Для повного touch-переходу враховано referrer того ж origin. Пряме посилання без власної історії веде до персонажів із збереженням редакції та `/no-ai`.

Модалки зберегли окрему дію «Закрити». Спроба назвати її «Назад» створила колізію з кроковим «Назад» у «Що нового»; її прибрано після реального прогону. Закриття продовжує споживати один запис історії, тож наступне «Назад» повертає сторінку, а не повторно закриває модалку.

### Ручне оновлення

Встановлений застосунок утрачає також браузерне перезавантаження. Додано «Оновити застосунок» у меню standalone. Воно використовує той самий `requestAppRestart`, що й підказка нової версії.

Ручна дія чекає завершення активного збереження, мережі й синхронізації офлайн-черги. Незбережені поля, відкрита форма/модалка або конструктор потребують підтвердження перед restart. Автоматичне оновлення таких станів не перериває.

### Захист збереження

Перевірки DOM недостатньо: серверна дія може зберігати правку після закриття редактора. У наявному offline action guard додано лічильник активних серверних дій. Дві паралельні дії тримають захист до завершення обох; `finally` скидає лічильник і після помилки. Операції офлайн-черги вже захищені її непорожнім станом.

## Що варто було зробити раніше

На початку треба було пройти список можливостей, які зникають разом з оболонкою браузера: «Назад», перезавантаження, зовнішні вікна, завантаження й вхід. Іконки та installability самі цього не перевіряють. Після цього — встановлення на пристрої, а вже потім вважати оболонку прийнятою.

Розділення на локальну реалізацію й приймання лишається явним: імітований standalone не стає фізичним прогоном через зелений тест. KR50.5 і Google/persisted-гейти KR50.4 відкриті. Production не змінено.

### Уточнення власника — 2026-10-11

Встановлення просуваємо лише на телефонах і планшетах. Спільний `findInstallPath` повертає `null` для desktop user agent навіть за наявності `beforeinstallprompt`; це прибирає і банер, і пункт меню, облік візитів та подію пропозиції. Визначення iPad через Macintosh + multi-touch збережено; ширина вікна не є критерієм. Банер тепер згадує телефон і планшет. Перевірки включають Windows з сенсорним екраном, Mac, Linux, iPhone, iPad з desktop UA й Android-планшет.

Холодний офлайн-запуск окремого Chrome-профілю після закриття процесу пройшов: кешований лист відкрився без мережі ([звіт](evidence/offline/report.json)). Це браузерна перевірка, а не приймання WebAPK чи iOS standalone.

Ручний перезапуск перевірено браузерним сценарієм: каталог перезавантажується, офлайн-перезапуск блокується, відмова від підтвердження в конструкторі залишає сторінку відкритою ([звіт](evidence/retrospective/manual-refresh-report.json), [меню](evidence/retrospective/manual-refresh-menu.png)). Після анімації зона натискання має 40 px.

Браузерна перевірка аудиторії пройшла у п’яти окремих Chrome-контекстах: desktop і narrow desktop — банер та меню приховані; iPhone, iPad, Android tablet — показані ([звіт](evidence/mobile-promotion/report.json)). Це емуляція пристроїв, без нативного встановлення.
