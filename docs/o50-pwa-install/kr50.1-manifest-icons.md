# KR50.1 — Повний маніфест і іконки з одного джерела

**Ціль:** [O50](README.md) · **Стан:** 🟡 реалізовано локально, очікує production-перевірки · **Оновлено:** 2026-10-10

## Мета

Chrome на Pixel 8 вважає сайт повноцінним застосунком (WebAPK), а не ярликом. Іконка на обох
платформах — той самий логотип на темному тлі, без білого кола й без знімка сторінки.

## Що робимо

1. **Квадратне джерело іконки.** `public/images/logo.png` — прозоре фіолетове дерево 494×500.
   Генератор кладе його по центру квадрата з тлом `#020617`:
   - для `any` і `apple-touch-icon` — з невеликим полем;
   - для `maskable` — у безпечній зоні: дерево займає не більше ~60 % сторони, бо Android
     обрізає маску до кола чи «сквіркла».

   Якщо власник дасть векторне чи більше джерело ([питання 1](questions.md#1-малюнок-іконки)),
   генератор бере його без інших змін.
2. **Генератор** `scripts/generate-app-icons.ts` (bun + `sharp`, вже в залежностях). Він пише в
   `public/icons/` та кореневу копію Apple-іконки з пункту 3:

   | Файл | Розмір | Для чого |
   |---|---|---|
   | `icon-192.png`, `icon-512.png` | 192, 512 | `purpose: any` |
   | `icon-maskable-192.png`, `icon-maskable-512.png` | 192, 512 | `purpose: maskable` |
   | `icon-monochrome-512.png` | 512 | `purpose: monochrome`: силует того ж дерева, білий на прозорому |
   | `apple-touch-icon.png` | 180 | iOS. Непрозорий: прозорі пікселі iOS заливає чорним |
   | `icon-96.png` | 96 | Спільна іконка швидких дій |

   Файли комітяться, як і `src/lib/generated/`. Генератор не входить у `prebuild`: іконки
   міняються рідко, а збірка не має залежати від растрування.
3. **`/apple-touch-icon.png` у корені** — копія 180 px, бо iOS і частина клієнтів шукають її
   там без тегу. Зараз ця адреса дає 404.
4. **Маніфест** `public/manifest.json`. Поля, яких бракує або які змінюються:
   - `id: "/char/home"` — стабільна ідентичність застосунку. Без неї Chrome бере `start_url`, і
     будь-яка майбутня зміна `start_url` дала б «другий застосунок»;
   - `icons` — п'ять записів із таблиці вище, `dragon.png` і `logo.png` звідси прибрати;
   - `screenshots` — 3–4 знімки `form_factor: "narrow"` (1080×2400, пропорція Pixel 8):
     список персонажів, лист, список заклинань, кубики. Знімаються Playwright-скриптом
     `scripts/capture-install-screenshots.ts` з підробленою сесією, як у браузерних аудитах
     (рецепт — у памʼяті проєкту, тема «Браузер і швидкість»).
     Кладуться в `public/icons/screenshots/`. Один `wide` — для повноти діалогу на планшеті;
   - `shortcuts` (довгий натиск на іконку Android): «Мої персонажі» `/char/home`, «Заклинання»
     `/spells`, «Бестіарій» `/bestiary`, «Створити персонажа» `/char/create`. Кожен — з
     іконкою 96 px того ж стилю. Набір — [питання 4](questions.md#4-швидкі-дії-з-іконки);
   - `display_override: ["standalone"]`, `prefer_related_applications: false`,
     `categories: ["games", "entertainment"]`;
   - `name` і `short_name` лишаються «ДнД українською» / «ДнД», якщо власник не вирішить
     інакше ([питання 2](questions.md#2-підпис-під-іконкою)).
5. **Заголовки кешу** в `src/lib/assets/cache-policy.ts`:
   - `/icons/:path*` — тиждень, як `/images/`;
   - `/manifest.json` — `no-cache`. Зараз `max-age=0`, тобто те саме, але явний рядок
     захищає від випадкової зміни дефолту;
   - `/sw.js` — у [KR50.4](kr50.4-updates-and-session.md).

## Гейти

- `tests/routes/web-app-manifest.test.ts` (без бази):
  - маніфест парситься;
  - кожна іконка й скриншот існує на диску, а її реальний розмір (через `sharp`) збігається з
    `sizes`;
  - є `any` 192 і 512, `maskable` 192 і 512, `apple-touch-icon.png` 180×180 без альфа-каналу;
  - `start_url` і кожен `shortcuts[].url` лежать у `scope`;
  - `id` не порожній.

  Довести червоним: прибрати `icon-512.png` зі списку; підмінити розмір maskable; дати
  apple-touch-icon з альфою.
- `bunx next build`. Потім **DevTools → Application → Manifest на `bun start`**: розділ
  Installability без помилок. Знімок «до» (з помилкою про іконки) і «після» — у журнал.

## Журнал

### 2026-10-10 — початок реалізації

На доручення власника почато KR50.1. Рекомендації з `questions.md` збережено:
фіолетове дерево з `public/images/logo.png`, тло `#020617`, назви «ДнД українською» / «ДнД».

Реалізовано локально:
- `bun scripts/generate-app-icons.ts`: any 192/512, maskable 192/512, monochrome 512,
  Apple 180 і shortcut 96. Коренева Apple-копія тотожна файлу в `public/icons/`.
- `manifest.json`: стабільний `id: /char/home`, нові іконки, чотири shortcuts,
  `display_override`, категорії та `prefer_related_applications: false`.
- `/icons/:path*` кешується тиждень, `/manifest.json` — `no-cache`.
- Спільний `APP_THEME_COLOR`; у layout додано `themeColor` та Apple-іконку.
  Решта standalone metadata, заставка й safe-area лишаються KR50.2.

Перевірки:
- 16/16 тестів: `web-app-manifest.test.ts` + `indexing-and-cache.test.ts`, із мертвою DB URL.
  Гейт перевіряє реальні PNG-розміри, scope, кольори, прозорість, маску й cache policy.
- Три окремі копії assets у `/tmp`: відсутня any 512, неправильний maskable size,
  Apple з альфою. Кожна дала assertion failure; основні файли не ламалися.
- Повторна генерація: SHA-256 усіх восьми PNG збігається.
- ESLint змінених TS-файлів пройшов.
- Maskable візуально переглянуто; весь знак у безпечному центральному колі радіусом 40%
  ([специфікація](https://www.w3.org/TR/appmanifest/#icon-masks)), перевірено пікселями.
- `bunx next build --webpack` у копії дерева `/tmp/spells-pwa-build.XvSGaK` з окремим
  `.next-pwa` і мертвою DB URL пройшов, включно з TypeScript і prerender. Початковий
  sandbox-прогін не зміг завантажити Google Fonts; повтор із мережевим доступом успішний.
  Наявні `.env` не копіювалися, `prebuild`/генерація каталогів не запускалися.
- HTTP smoke цієї production-збірки на `127.0.0.1:3207`: manifest і всі 8 адрес іконок
  повернули 200; cache headers збіглися; на `/offline` є `theme-color`, manifest і
  `apple-touch-icon`. Власний процес сервера зупинено, `:3000` не використовувався.
- `clean-code-guard`: у генераторі розділено побудову monochrome-силуету й запис PNG;
  після зміни lint та всі 16 тестів повторно пройшли.

Залишок: Playwright capture-скрипт і narrow/wide screenshots із тестовою сесією;
обовʼязковість screenshots у гейті; DevTools Installability «до/після»;
перевірка 200 для Apple-іконки після дозволеного деплою. Локальний Postgres на початку
сесії був вимкнений. KR не закрито; коміту, пушу й деплою не було.

### 2026-10-10 — скриншоти й Chrome Installability

Додано `scripts/capture-install-screenshots.ts`. Запуск:

```sh
PWA_CAPTURE_ORIGIN=http://127.0.0.1:3207 DATABASE_URL='<окрема локальна база *_test>' AUTH_SECRET='<секрет тестового сервера>' bun scripts/capture-install-screenshots.ts
```

Потрібні запущений ізольований сервер і встановлений Chrome. Скрипт відмовляється від
production, порту 3000 і шаблону `spells_test`. Створює власного користувача та три
демонстраційні персонажі 2014, підписує JWT для тестового сервера, знімає галерею та видаляє
свої записи. Кожному запуску — новий Chrome context; service worker для capture заблокований.
Реліз відмічається переглянутим лише в localStorage цього контексту. База і AUTH_SECRET
сервера та скрипта мають збігатися.

Знімки в `public/icons/screenshots/`: персонажі, лист, заклинання й завершений кидок —
1080×2400 (`360×800 CSS`, DPR 3); широкий каталог — 1280×800. Зображення переглянуті:
без announcement, skeleton або порожнього списку. Capture чекає видимих карток, шрифтів
і видимих зображень; lazy-картинки поза екраном не блокують знімання.

Доказ Chrome Installability: [JSON DevTools Protocol](evidence/installability-2026-10-10.json).
Chrome **154.0.8037.58**, macOS, localhost `3207`, production-збірка попереднього проходу.
Старий manifest підставлено через Playwright route тільки в тестовому профілі:
`Page.getInstallabilityErrors` → `no-acceptable-icon`. Новий manifest → порожній список;
`Page.getAppManifest` також без parsing errors. Два окремі тимчасові persistent-профілі;
service worker активний. Скрін DevTools UI замінено безпосередньою відповіддю його API.
Сторінка перевірки — `/offline`, тому це доказ manifest/SW, а не Google-входу чи роботи листа
в установленому застосунку. Реальні Pixel/iPhone лишаються KR50.5.

17/17 тестів manifest/cache, ESLint і TypeScript пройшли. Четверта навмисна поломка
`screenshots: []` теж дала assertion failure на копії в `/tmp`; три попередні повторно
відхилено. Full production build уже пройшов до цього: нові зміни — public assets і
capture-інструмент, для останнього окремо виконано `tsc --noEmit` у копії дерева.

`clean-code-guard`: розділено DB lifecycle, browser lifecycle і capture; Prisma закривається
навіть за помилки створення користувача, а всі Chrome contexts закриваються з браузером.
Файли production/UI не змінювалися в цьому проході.

Для знімання запущено локальний PostgreSQL і створено окрему копію `spells_test`;
production не читався. Власні Chrome і Next-процеси зупинено після перевірок.
Локальний PostgreSQL залишено запущеним; власну тимчасову PWA-базу видалено після перевірок.

**Залишок KR50.1:** перевірити `/apple-touch-icon.png` на production після дозволеного
деплою. Реалізація готова локально; можна переходити до KR50.2 без очікування деплою.
Коміту, пушу й деплою не було.
