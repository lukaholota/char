# KR50.3 — «Встановити застосунок»

**Ціль:** [O50](README.md) · **Стан:** 🟡 реалізовано локально 2026-10-10; очікує production і пристроїв · **Залежить від:** [KR50.1](kr50.1-manifest-icons.md)

## Мета

Гравець дізнається, що сайт можна встановити, і робить це в один-два дотики. На Android —
системний діалог. На iOS, де системного діалогу немає, — покрокова підказка саме для його
браузера. Усередині вже встановленого застосунку пункт не показується.

## Що робимо

1. **Чиста функція вибору шляху** — `src/lib/pwa/install-platform.ts`:
   `findInstallPath({ userAgent, isStandalone, hasInstallPrompt })` повертає один із варіантів:

   | Шлях | Коли | Що бачить гравець |
   |---|---|---|
   | `installed` | `display-mode: standalone` або `navigator.standalone` | нічого |
   | `native-prompt` | Chrome/Edge/Samsung із перехопленою `beforeinstallprompt` | системний діалог Android |
   | `ios-safari` | iPhone/iPad, Safari | підказка: «Поділитися» → «На початковий екран» → «Відкрити як вебзастосунок» → «Додати» |
   | `ios-other-browser` | iPhone, Chrome/Firefox/Edge на iOS | та сама підказка для меню цього браузера (з iOS 16.4 вони теж уміють) |
   | `in-app-browser` | вбудований браузер Telegram, Instagram, Facebook тощо | «Відкрийте сайт у Safari / Chrome» + кнопка «Скопіювати посилання» |
   | `android-menu` | Android без перехопленої події (Firefox, подію вже витрачено) | «Меню ⋮ → Додати на головний екран / Встановити» |

   Посилання на лист гравці кидають у чатах, тож вбудований браузер Telegram — частий
   випадок, а встановити з нього не можна ні на iOS, ні на Android.
2. **Перехоплення `beforeinstallprompt` до гідрації.** Подія може прийти раніше, ніж змонтується
   React. Невеликий inline-скрипт у `<head>` (так само, як `RESERVE_FIRST_POPSTATE_LISTENER_SCRIPT`)
   робить `preventDefault()` і кладе подію в `window.__deferredInstallPrompt`. Клієнтський модуль
   `src/lib/pwa/install-prompt.ts` забирає її звідти й підписується на наступні.
3. **Точка входу.** Пункт «Встановити застосунок» у `NavExtraMenu` — завжди, крім шляху
   `installed`. Додатковий ненавʼязливий банер на `/char/home` —
   [питання 5](questions.md#5-наскільки-наполегливо-пропонувати):
   - з другого візиту;
   - закривається хрестиком;
   - після закриття мовчить 30 днів (localStorage, у `try/catch`).
4. **Підказка iOS** — шторка з трьома кроками й маленькими схематичними іконками
   («Поділитися», «На початковий екран»). Тексти пунктів меню взяти зі знімків реального
   iPhone з українською мовою в KR50.5, не вгадувати. Якщо офлайн-черга не порожня
   (`src/lib/offline/queue.ts`), шторка попереджає: встановлений застосунок на iOS має окреме
   від Safari сховище — спершу дочекатися, поки зміни надішлються
   ([KR50.4](kr50.4-updates-and-session.md)).
5. **PostHog** (назви — за [POSTHOG-ANALYTICS.md](../POSTHOG-ANALYTICS.md)):
   - суперпропертя `display_mode: browser | standalone` на кожній події — головна метрика
     цілі, частка сесій зі встановленого застосунку;
   - `app_install_offered` `{ path, placement }`;
   - `app_install_prompt_result` `{ outcome: accepted | dismissed }`;
   - `app_installed` (подія `appinstalled`, лише Chromium);
   - `app_ios_instructions_opened`.

   Додати плитку на дашборд у `docs/posthog-dashboards.json`.

## Гейти

- Юніт на `findInstallPath`: таблиця реальних user-agent рядків:
  - Pixel 8 Chrome;
  - iPhone Safari, iPhone Chrome (`CriOS`);
  - Telegram iOS і Android, Instagram;
  - Samsung Internet;
  - Android Firefox;
  - вже standalone.

  Довести червоним: прибрати перевірку standalone; сплутати `CriOS` із Safari.
- Компонентний тест пункту меню: прихований у `installed`; на `native-prompt` клік викликає
  `prompt()` і шле `app_install_prompt_result`.
- Playwright Chromium: `beforeinstallprompt` підроблено через `dispatchEvent` до гідрації —
  пункт меню викликає збережену подію.

## Журнал

### 2026-10-10 — Локальний вхід у встановлення

У меню поруч зі швидким пошуком є «Встановити застосунок». `findInstallPath` розрізняє
standalone, збережений системний prompt, Safari/CriOS та інші iOS-браузери, відомі маркери
браузерів чатів і fallback через меню браузера. iPad з desktop UA розпізнається за Macintosh
і touch points. Вбудований браузер без власного UA-маркера надійно визначити неможливо;
це ще треба звірити на реальному Telegram у KR50.5.

Inline-скрипт у head перехоплює подію до гідрації. Prompt витрачається один раз,
`prompt()` викликається з початкового натискання; після відмови лишається fallback.
`appinstalled`, `display-mode: standalone` і `navigator.standalone` прибирають точку входу.
Інструкція живе поза меню, тому закриття меню не прибирає її; спільний Dialog підтримує «Назад».

Шторка має три дії з іконками, окрему пораду для інших iOS-браузерів та інструкцію
для браузера чату. Копіюється поточна адреса, включно з query; якщо clipboard недоступний,
можна виділити адресу вручну. За ненадісланих правок iOS показує попередження про
окреме сховище. Читається чинна offline queue; синхронізація й офлайн-операції не змінені.

**Точні українські назви системних пунктів не вигадані:** текст описує дії нейтрально.
Після знімків українського iPhone в KR50.5 його треба уточнити. Сценарій звірено з
[Apple](https://support.apple.com/en-lamr/guide/iphone/iphea86e5236/ios), одноразовий prompt —
з [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event).

На `/char/home` банер показується з другого монтування сторінки, приховується на 30 днів
після закриття. Strict Mode не подвоює візит. Заблокований localStorage вимикає лише банер;
меню лишається доступним. Встановлений застосунок не записує візити банера.

Аналітика через чинний lazy PostHog: `app_install_offered` `{path, placement}`,
`app_install_prompt_result` `{outcome}`, `app_installed`, `app_ios_instructions_opened`.
Прихована responsive-версія меню не дублює показ пропозиції. `display_mode` додається
до клієнтських подій при постановці в чергу, реєструється як superproperty й має fallback
у `before_send` для SDK-подій. Серверні події без браузерного контексту не позначаються
довільно як browser/standalone.

Чотири плитки додано до локального визначення дашборда «Аудиторія та каталоги»:
сесії за режимом, способи пропозиції, результат prompt, встановлення Chromium / інструкції iOS.
Сесії використовують `unique_session`,
[підтримуваний PostHog](https://posthog.com/docs/data/sessions).
У `docs/posthog-dashboards.json` — `pendingInsights` із назвами, без вигаданих бойових ID.
**До PostHog API зміни не застосовані**, тестові captures у production не надсилались.
