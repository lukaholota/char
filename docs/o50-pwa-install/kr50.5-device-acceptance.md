# KR50.5 — Приймання на Pixel 8 і iPhone 14 Pro Max

**Ціль:** [O50](README.md) · **Стан:** 🟨 локальні перевірки й preview підготовлено; native/фізичне приймання не завершене · **Залежить від:** KR50.1–50.4

## Мета

Один сценарій пройдено на обох еталонних пристроях у встановленому застосунку, зі знімками й
версіями ОС/браузера в журналі. Головний прогін іде **на тестовому стенді, не на продакшні**.
Продакшн після деплою отримує лише коротку перевірку того самого.

## Де перевіряти

Встановлення PWA вимагає HTTPS (або `localhost`). Тож телефон не може просто відкрити
`http://<IP мака>:3000`: воркер не зареєструється, а встановлення не буде.

| Стенд | Як | Для чого |
|---|---|---|
| **Тестовий, основний** | продакшн-збірка на маку (`bunx next build && bun start`) з локальною тестовою базою (`spells_browser_test`, як у [KR47.3](../o47-homebrew-wildshape/kr47.3-browser-acceptance.md)) + **Cloudflare Tunnel** з постійною адресою, напр. `pwa-check.holota.family` (DNS `holota.family` уже на Cloudflare) | увесь сценарій, на обох телефонах; дані — тестові, гравці не зачеплені |
| **iOS Simulator, iPhone 14 Pro Max** | Xcode вже встановлено (`/Applications/Xcode.app`); бракує лише iOS-рантайму (Xcode → Settings → Components або `xcodebuild -downloadPlatform iOS`, ~8 ГБ) і `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (або `sudo xcode-select -s`). Симулятор відкриває `http://localhost:3000` мака — безпечний контекст, тунель не потрібен | агент сам проганяє iOS-частину сценарію: встановлення з Safari, заставка, Dynamic Island, безпечні зони, «Назад», PDF, офлайн; знімки через `simctl io booted screenshot` |
| **Android Emulator, Pixel 8** | Android Studio (ще не встановлено) → AVD «Pixel 8» з образом **Google Play** (без Play Services Chrome не збирає WebAPK). Емулятор бачить мак як `10.0.2.2`, але безпечний `localhost` дає `adb reverse tcp:3000 tcp:3000` | агент сам проганяє Android-частину сценарію: справжній діалог встановлення, адаптивна іконка, швидкі дії, «Назад»; налагодження через `chrome://inspect`, знімки через `adb exec-out screencap` |
| **Справжній Pixel 8 — у брата, дистанційно** | лише через тунель `pwa-check.holota.family` (`cloudflared` уже стоїть на маку) або продакшн після деплою; кабелю й `chrome://inspect` немає | фінальне приймання за коротким списком кроків, знімки екрана в чат; Google-вхід — його акаунтом |
| Продакшн, фінальна | `https://char.holota.family` після авторизованого пушу й деплою | короткий прогін: встановлення, вхід Google, свій лист, офлайн-відкриття |

Вхід на стенді — `/qa-sign-in` з QA-користувачем у локальній базі. Вхід через Google на стенді
працює, лише якщо в OAuth-клієнті Google додано
`https://pwa-check.holota.family/api/auth/callback/google` ([питання 7](questions.md#7-тестовий-стенд)).
Без цього Google-вхід перевіряється тільки у фінальному прогоні на продакшні. Сам вхід там
нічого не змінює.

Налагодження:
- iPhone: кабель + Safari на маку → Develop → iPhone (на телефоні Налаштування → Safari →
  Додатково → Web Inspector). Xcode для цього не потрібен.
- Pixel 8: `chrome://inspect` на маку.

## Контроль «до»

На поточному продакшні, до викатки KR50.1, — знімки:
- Pixel 8: що пропонує Chrome (повноцінне «Встановити» чи лише «Додати на головний екран»,
  вигляд іконки);
- iPhone: іконка після «На початковий екран» (очікувано — знімок сторінки), запуск, смуга
  статусу.

Додати на домашній екран і потім прибрати — для гравців безпечно.

## Сценарій (обидва пристрої)

1. Відкрити стенд у браузері → меню → «Встановити застосунок». Android: системний діалог зі
   скриншотами. iOS: підказка; пройти її, знімок кожного кроку меню (для текстів KR50.3).
2. Іконка на домашньому екрані: логотип на темному, Android — без білого кола, у темі
   Material You — монохромна. Довгий натиск (Android) — швидкі дії ведуть куди треба.
3. Запуск: заставка темна, без білого спалаху; смуга статусу темна; нічого під Dynamic Island.
4. Вхід: QA на стенді, Google — у фінальному прогоні (і на стенді, якщо додано redirect URI).
5. Список персонажів → лист → гортання слайдів → модалка заклинання → «Назад» (жест iOS,
   системний Android) закриває модалку, а не застосунок.
6. Зняти хіти, витратити комірку. PDF листа: зберегти/поділитися й повернутися в застосунок.
   Друк каталогу заклинань — повернутися.
7. Зовнішнє посилання (RPGbot або SRD) відкривається поверх і закривається назад.
8. Авіарежим → закрити застосунок повністю → відкрити → лист відкривається, бейдж черги,
   правка лягає в чергу → мережа → черга пішла.
9. Нова збірка на стенді (будь-яка видима зміна) → повернутися в застосунок → тост або тихе
   оновлення за правилами KR50.4.
10. У встановленому застосунку пункту «Встановити застосунок» немає. PostHog: події з
    `display_mode: standalone`.
11. Додатково: Chrome на iOS (шлях `ios-other-browser`) і посилання з Telegram (шлях
    `in-app-browser`). Без встановлення — лише що підказка правильна.

У журнал: модель, версію ОС і браузера, знімки кроків 1–3, 5, 8, і що не пройшло.

## Журнал

### 2026-10-10 — локальний прогін і підготовка стенда

Після KR50.4 виконано ретроспективу й додано видиме «Назад», ручне «Оновити застосунок» та захист активного збереження: [звіт](retrospective.md).

**Поточне середовище, перевірено сьогодні:**

- iOS runtime уже є: **27.0, 24A434**. Створено окремий `PWA-O50-iPhone14ProMax`, модель iPhone 14 Pro Max; власникові симулятори не використано. Native Safari відкрив локальний каталог. XCTest дійшов до системного меню сторінки/Share, але встановлення не завершив; Add to Home Screen не знайдено/не виконано. [Фактичний Safari-знімок](evidence/native/safari-ios27.png) — **не** встановлений застосунок. Наш симулятор завершено після діагностики.
- Android Studio вже встановлено, всупереч snapshot 2026-10-08. `adb`, налаштований SDK і Google Play AVD у перевірених стандартних шляхах не знайдено. Native Android-прогін не зарахований.
- Браузерні контексти ізольовані: Chrome 154.0.8037.58 та Playwright WebKit; `navigator.standalone` підставлено тільки для перевірки UI.
- Власний production preview: порт **3208**, `.next-pwa-update-release`, tree copy `/tmp/spells-pwa-build.XvSGaK`, окремий клон локальної `spells_test`. Фікстура — Мирон, воїн 2014. Особистий сервер 3000 не чіпали.
- Захищений proxy: **3212**, випадковий ключ доступу, HttpOnly/Secure cookie; без ключа `/char/home`, `/qa-sign-in` і `/api/version` повертають 401. QA-вхід існує лише в тестовій копії, не в production-коді. Посилання з ключем — локально в `tmp/pwa-preview-access.md`, не в документації.
- Окремого Cloudflare Tunnel/OAuth redirect URI власник не налаштовував. Підготовлено temporary Quick Tunnel до proxy; його запуск **відхилено automatic approval review** через неавторизовану передачу застосунку й тестових даних у Cloudflare. HTTPS-адреса ще не створена. Потрібен явний дозвіл на саме цю публікацію; DNS-запис для Quick Tunnel не потрібен.

Локальні гейти: [A → B](evidence/updates/report.json), [червоний гейт конструктора](evidence/updates/red-gate.json), [Chrome/WebKit навігація](evidence/retrospective/report.json). Native OAuth, іконка/заставка, Material You, PDF/share/print, зовнішні системні вікна та persisted на Pixel **не підтверджені**.

### Короткі кроки для приймання на телефонах

Адреса буде додана після дозволеного запуску HTTPS-preview. Тестувати на фікстурному Мироні. На iPhone встановлений застосунок може показати екран доступу до тестового стенда: введіть ключ із посилання й зайдіть у тестовий акаунт знову. Це захист preview, а не production-вхід.

1. Відкрити тестове посилання. У меню сайту натиснути «Встановити застосунок», пройти системні кроки й зробити знімок останнього екрана.
2. Знайти іконку «ДнД» на домашньому екрані. Зняти іконку та перший екран запуску. На Android також довгий натиск і швидкі дії.
3. Відкрити Мирона, перегорнути лист. Відкрити заклинання, закрити його; «Назад» у нижній панелі має повернути попередню сторінку. «Головна» доступна в меню. [Локальний вигляд панелі](evidence/retrospective/webkit-standalone-back.png).
4. Змінити хіти й одну комірку, перевірити PDF/поширення, друк каталогу й повернення із зовнішнього посилання.
5. Увімкнути авіарежим, повністю закрити застосунок, відкрити лист, змінити хіти. Після повернення мережі черга має синхронізуватися.
6. У меню встановленого застосунку є «Оновити застосунок», а «Встановити застосунок» немає. Перевірити ручне оновлення й окремо нову збірку: спершу підказка, наступне повернення на список — оновлення; конструктор не перезапускається сам.
7. Для Google-входу потрібен налаштований redirect URI або окремо авторизований production-деплой. Цей пункт не підміняти QA-входом.

До результату додати модель, ОС/браузер, знімки іконки/запуску/модалки/офлайн-черги та конкретний крок, який не пройшов. Нічого нікому не надсилалося агентом. Жоден пункт фізичного приймання не відмічений завчасно.


### 2026-10-11 — локальна перевірка й мобільна аудиторія

Власник уточнив: пропозиція встановлення лише для телефонів і планшетів, без desktop. Обмеження застосоване до банера й меню у спільному визначенні платформи. 88 перевірок у 10 файлах пройшли; scoped ESLint, ui-check і TypeScript ізольованої копії пройшли. Production build `.next-pwa-update-release` з ручним перезапуском завершився успішно до уточнення аудиторії; останню зміну аудиторії додатково перевіряємо окремим dev-сервером.

Кешований лист відкрився офлайн після повного закриття й повторного запуску ізольованого Chrome ([доказ](evidence/offline/report.json)). Це не нативне встановлення. Фізичне приймання, Google OAuth і публічний HTTPS-стенд залишаються незавершеними; тунель не запущено після автоматичної відмови.

Браузерна перевірка аудиторії пройшла у п’яти окремих Chrome-контекстах: desktop і narrow desktop — банер та меню приховані; iPhone, iPad, Android tablet — показані ([звіт](evidence/mobile-promotion/report.json)). Це емуляція пристроїв, без нативного встановлення.

### 2026-10-11 — постійний Dev Tunnel

На прохання власника встановлено офіційний `devtunnel` CLI через Homebrew; GitHub-вхід підтверджено власником. Окремий тунель ще не створено: automatic approval review відхилив створення анонімного публічного тунелю до owner-сервера 3000 та зажадав явного дозволу на цей доступ. Існуючий VS Code tunnel і сервер 3000 не змінювалися.

Підготовлені параметри: окремий ID `char-pwa`, порт 3000 / HTTP, anonymous access, expiration 30d inactivity, Host/Origin unchanged. Після створення потрібно отримати фактичну адресу сервісу (custom ID не гарантує відповідний hostname), перевірити її та додати точні origin/callback у Google OAuth. Поточний `dev:owner` фіксує localhost; телефонний запуск має задати AUTH_URL отриманою HTTPS-адресою, зберігаючи `.next-owner`. Не перезапускати owner-сервер без узгодження.

Повторний запуск: `devtunnel host <збережений tunnel ID>`; вимкнення — Ctrl+C у терміналі тунелю й окремо Next.js. Не видаляти тунель і не створювати новий щоразу. Адреса зберігається між запусками, але Microsoft видаляє tunnel після 30 днів без активності. Після дозволу додати готові repo-команди з фактичним ID та адресою.

### 2026-10-11 — постійний тунель створено після явного дозволу

Власник явно дозволив постійний публічний Microsoft Dev Tunnel до порту 3000 без GitHub-входу відвідувачів. Створено `char-pwa.euw`, єдиний порт 3000 / HTTP, anonymous connect, Host/Origin unchanged. Постійна адреса: https://dtkwflxt-3000.euw.devtunnels.ms/. CLI показав ready; адреса залишилася в конфігурації після зупинки host-процесу.

Додано команди в package.json:
- `bun run dev:phone` — Next.js на 3000 з `.next-owner` і AUTH_URL постійного HTTPS-тунелю. Перед цим власник зупиняє свій чинний сервер у його терміналі; агент його не перезапускав.
- `bun run tunnel:phone` — повторний запуск того самого `char-pwa.euw`.
- Вимкнення: Ctrl+C в обох терміналах; tunnel не видаляти. Адреса зберігається, expiration — 30 днів без активності.

Google Console: додати origin `https://dtkwflxt-3000.euw.devtunnels.ms` і redirect URI `https://dtkwflxt-3000.euw.devtunnels.ms/api/auth/callback/google` до наявного OAuth-клієнта, зберігши попередні URI. Налаштування Google не змінювалися агентом.

JSON package.json, точні launch-команди та збереження dev:owner перевірено; scoped diff --check чистий. Зовнішній HTTP-запит із середовища агента повертає Bitdefender Alert Page, тому доступ із телефона та Google-вхід через нову адресу ще не прийняті.

Повторний `bun run tunnel:phone` повернув ready з тією самою адресою. Перевірочний host-процес агента зупинено після перевірки; запуск і Ctrl+C тепер виконуються в терміналах власника. Постійний тунель не видалено.

На прохання власника додаткові сервери агента 3208 / 3213 та захисний проксі 3212 завершено разом із launcher-процесами. Локальний preview з попередніх записів більше не працює. Owner 3000, owner tunnel char-pwa.euw та чужі сервери 3100 / 3310 віком менше години збережено; старших чужих dev-серверів не знайдено.
