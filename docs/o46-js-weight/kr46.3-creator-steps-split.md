# KR46.3 — Кроки конструктора окремими чанками

**Стан:** 🔵 заплановано

## Що не так

`MultiStepForm` статично імпортує ~20 форм кроків (раси, класи, опції, заклинання, спорядження,
імʼя…), тож на першому кроці браузер уже завантажив і розібрав код останнього, разом із
markdown-рендерером, `@radix-ui/react-select`, `react-hook-form` та ін. — ~200 КБ власного коду
плюс залежності.

## Принцип (власник, 2026-09-26)

Модалки й кроки мають відкриватися без затримки, але не треба вантажити те, до чого ще 20 кроків:

- на старті — лише те, що потрібно, щоб правильно **побудувати список кроків** (`resolveCreationSteps`
  і умови з даних) і показати **поточний** крок;
- код наступного кроку — у фоні **одразу після** переходу на поточний, а не на кліку «Далі»,
  щоб «Далі» відкривало вже готовий крок.

Той самий принцип — для описів карток, якщо їх колись винесуть із даних (зараз не варто:
заміри в [README](README.md#навіщо)).

## Як зробити

1. Кожна форма кроку — `next/dynamic` з фолбеком без стрибка висоти (не скелет із затримкою
   Suspense: див. памʼять про ≥300 мс паузи React на кожному вкладеному фолбеку).
2. Після переходу на крок N — `import()` форми кроку N+1 (і N−1, якщо ще не завантажена):
   мапа `stepId → () => import(...)` поруч із `creation-step-resolver.ts`, щоб крок і його код
   жили в одному місці.
3. Логіку — в сусідній модуль, не в `MultiStepForm.tsx` (гейт `check:ui-decomposition`).

## Критерій приймання

- Перший крок `/char/create` не тягне чанків інших кроків; наступний крок завантажується у фоні
  до кліку «Далі».
- Жорсткий перехід на будь-який крок (чернетка з `currentStep: N`) відкриває його без помилок.
- Playwright: пройти конструктор до кінця на Pixel ×4 — жоден «Далі» не чекає мережі.
- Тести `creator-steps-projection`, `creation-step-*`, e2e `creation.spec.ts` зелені.
- Замір «до» / «після» за [методикою O46](README.md#як-міряти).
