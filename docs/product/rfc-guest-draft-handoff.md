# RFC: перенесення чернетки між браузерами

Статус: **варіант 0 схвалено власником і реалізовано 2026-10-17** (`src/lib/utils/draft-link.ts`); варіант 1 — не реалізовувати без схвалення. Дата: 2026-10-16.
Контекст: [auth-funnel-audit.md](auth-funnel-audit.md), проблема P13.

## Проблема

Чернетка конструктора живе лише в localStorage браузера
([persFormStore.ts:11-17,122-139](../../src/lib/stores/persFormStore.ts)). Людина з Threads, Instagram чи
Facebook проходить 8–12 кроків у вбудованому браузері, де Google не дає увійти. Скопійоване посилання
відкриває в Safari/Chrome порожній конструктор. За 30 днів так загубилися всі 90 стартерів із Threads.

Сьогоднішній реліз прибирає блокування й дає скопіювати поточний шлях, але **не переносить прогрес**.

## Коли це варто робити

Лише якщо після 14 днів нової інструментації ([auth-funnel-analytics.md](auth-funnel-analytics.md), Funnel 3):
- вбудований браузер ≥10% кваліфікованих спроб, **і**
- люди копіюють посилання (≥20% показів), але <30% продовжених спроб доходять до створення.

Інакше перенесення маршруту достатньо, і цей RFC не потрібен.

## Цілі й межі

- Перенести **лише чернетку конструктора** (`formData`, `currentStep`, область) з одного браузера в інший
  на тому самому пристрої.
- Без гостьових акаунтів, без привʼязки чернетки до користувача, без зміни входу.
- Не переносити сесію, cookie, дані акаунта й нічого з інших сховищ.

## Варіант 0 — чернетка у фрагменті посилання (без бази)

1. Кнопка «Скопіювати посилання з прогресом» серіалізує чернетку, стискає (`CompressionStream`,
   deflate-raw) і кладе в **фрагмент**: `https://char.holota.family/char/create#draft=<base64url>`.
2. На відкритті конструктор читає фрагмент, перевіряє його схемою чернетки (zod, межа розміру),
   пропонує «Продовжити збережений прогрес?» і одразу прибирає фрагмент через `history.replaceState`.

| Плюс | Мінус |
|---|---|
| Без бази, DDL, TTL, токенів, rate limit | Посилання **містить** чернетку: хто отримав посилання, бачить вибори й імʼя персонажа |
| Фрагмент не йде на сервер, у логи nginx і в `Referer` | Довжина URL: оцінка 2–6 КБ; деякі месенджери можуть обрізати при пересиланні (не перевірено) |
| Працює офлайн і в будь-якому браузері | Аналітика: `$current_url` у PostHog містить hash — потрібно вирізати `#draft` у `before_send` і в Sentry |

Перед вибором варіанта 0 треба виміряти розмір реальних чернеток (локально, на фікстурах 2014 і 2024).
Якщо медіана >8 КБ — варіант 1.

## Варіант 1 — короткоживуча серверна чернетка

### Потік

1. У вбудованому браузері тап «Перенести в браузер» → серверна дія `createDraftHandoff(draft)`.
2. Сервер перевіряє чернетку схемою, генерує токен, зберігає **хеш** токена і чернетку, повертає
   `https://char.holota.family/char/handoff#t=<token>`.
3. Людина копіює посилання (див. обмеження виходу з WebView в аудиті) і відкриває в Safari/Chrome.
4. Сторінка `/char/handoff` читає токен із фрагмента, **одразу** прибирає його з адреси й викликає
   `redeemDraftHandoff(token)` (POST).
5. Сервер атомарно погашає токен і повертає чернетку. Клієнт кладе її в localStorage потрібної області
   й веде на конструктор. Далі — звичайний вхід через Google.

### Схема (SQL для власника, **не застосовано**)

```sql
CREATE TABLE draft_handoff (
  draft_handoff_id bigserial PRIMARY KEY,
  token_hash       char(64)    NOT NULL UNIQUE,
  draft_scope      varchar(64) NOT NULL,
  payload          jsonb       NOT NULL,
  created_at       timestamptz NOT NULL DEFAULT now(),
  expires_at       timestamptz NOT NULL,
  redeemed_at      timestamptz,
  CONSTRAINT draft_handoff_payload_size CHECK (pg_column_size(payload) <= 65536)
);
CREATE INDEX draft_handoff_expires_at_idx ON draft_handoff (expires_at);
```

Таблиця без `user_id` і без IP: чернетка нікому не належить.

### Безпека

| Вимога | Рішення |
|---|---|
| Випадковий непрозорий токен | `randomBytes(32)` → base64url (256 біт). Не UUID, не автоінкремент |
| Хешоване зберігання | У базі лише `sha256(token)`. На відміну від `PersShareToken.token`, що зберігається відкрито |
| Тимчасова чернетка, короткий TTL | `expires_at = now() + 30 min` |
| Політика погашення | Один раз: `UPDATE draft_handoff SET redeemed_at = now() WHERE token_hash = $1 AND redeemed_at IS NULL AND expires_at > now() RETURNING payload`. Друга спроба — «Посилання вже використане або застаріло», без підказки, яке саме |
| Повтор і перебір | Rate limit на створення (наприклад 10 на годину з IP, у памʼяті процесу) і на погашення (30 невдалих спроб на годину з IP). Однакова відповідь на «немає», «використано», «прострочено» |
| Прострочення й очищення | `DELETE FROM draft_handoff WHERE expires_at < now() - interval '1 day'` при кожному створенні (дешево завдяки індексу) або щоденним завданням |
| Власність і привʼязка до акаунта | Чернетка нічия. Після погашення вона існує лише в localStorage нового браузера. Персонаж створюється звичайним `createCharacter` від імені того, хто увійшов. Жодного «claim» гостьового акаунта |
| CSRF | Обидві дії — server actions Next.js (POST, перевірка Origin). Погашення не через GET, щоб префетч і сканери посилань не «зʼїли» токен |
| IDOR | Пошук лише за хешем токена; ідентифікатори рядків назовні не виходять |
| Без секретів у PostHog | Токен не кладеться в жодну подію. `before_send` вирізає `#t=` і шлях `/char/handoff` з усіх URL-полів. Подія `draft_handoff_redeemed {ok, reason}` — без токена |
| Витік через Referer, логи, replay | Токен у **фрагменті**: не йде на сервер, у логи nginx, у `Referer`. `/char/handoff` не записується в replay і має `Referrer-Policy: no-referrer`. Sentry `beforeSend` вирізає фрагмент |
| Розголошення посилання | Посилання = 30 хвилин і одне використання. Текст поруч: «Не пересилайте це посилання: воно відкриває вашу чернетку». Чернетка не містить даних акаунта |
| Валідація вмісту | Та сама zod-схема чернетки на створенні й погашенні; межа 64 КБ; невідомі поля відкидаються |

### Тести

- `tests/rules` або `src/server/db`: створення → погашення → повторне погашення відхилено; прострочений
  токен; неіснуючий токен; однакова відповідь для трьох відмов; хеш у базі не дорівнює токену.
- Інтеграційний тест на `spells_test`: конкурентні погашення — успішне лише одне.
- Компонент: фрагмент прибрано до першого `$pageview`; подія без токена.
- Ручна перевірка на пристроях: Threads iOS/Android → Safari/Chrome.

### Вартість

DDL від власника, дві серверні дії, сторінка `/char/handoff`, очищення, rate limit, тести. Оцінка — 1–2
робочі дні з рев'ю безпеки.

## Альтернативи, які відкинуто

- **Гостьовий акаунт з подальшим claim** — зміна моделі користувачів і входу; ризик злиття чужих даних.
- **Magic link з чернеткою** — потребує пошти; посилання відкривається в іншому браузері, сканери
  погашають токен (див. [auth-alternatives.md](auth-alternatives.md)).
- **Спільний localStorage** — технічно неможливо між WebView і Safari.
