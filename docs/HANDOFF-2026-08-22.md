### 3. Бестіарій — стеля досягнута

| | Перекладено | Стеля джерела | Лишилось перекладного |
|---|---:|---|---:|
| 2014 | **607** | 607 з 934 | **0** |
| 2024 | **491** | ~494 з 521 | **0** |

**Ключовий факт для планування:** 327 сторінок aidedd 2014 і 13 сторінок 2024 мають **порожній
статблок** — сама назва дії без тексту механіки. Тексту для них не існує в джерелі, і власник
раніше вирішив його не вигадувати.

Корелят порожнечі — **не «поза SRD»**, як здавалося (261 з 508 непорожніх 2024 теж поза SRD,
включно з `mind-flayer` і `displacer-beast`), а **мітка книги**: `Forgotten Realms: Adventures in
Faerûn` — 7 сторінок, 7 порожніх, тобто aidedd не публікує цілу книжку. Усе з міткою `(BR)` —
337 сторінок, 0 порожніх.

**Наслідок для правила «не генерувати івенти, поки не перекладемо все з aidedd»:** якщо ворота —
«всі 934», вони не відчиняться ніколи. Якщо «все, що можна перекласти» — вони вже відчинені.
Формулювання варто виправити.

**`flesh-golem` закривається сьогодні** — у SRD 5.2.1 є його статблок саме з полем `Speed`,
якого бракує на aidedd. Три шаблони-виклики впираються не в джерело, а в парсер ПС.

Від найдешевшого до найдорожчого, і в порядку спадання ризику.

1. **Відкрити в браузері головну обох редакцій і пошук.** Це найдешевша перевірка з усіх і
   закриває найбільший ризик. Робити **до** будь-яких нових правок.
2. **Зняти розмір чанків** — `bunx next build` (НЕ `bun run build`), порівняти з тим, що
   `src_lib_generated_creatures_json_*.js` більше не тягнеться 35 сторінками.
3. **Прогнати `bun run test:integration`.**
4. **Перевірити Б1–Б3, Б7** — вони перевіряються очима за хвилину кожен.
5. **Магічні предмети, решта ~443** — конвеєр проторований, це робота на дешевшій моделі.
6. **Переклад правил 2014** — після рішення власника про джерела.
7. **Кодмод `next/link`** для режиму без ШІ — механічна робота, але зачіпає весь репозиторій,
   тому робити тоді, коли ніхто інший у дереві не пише.

## Пастки, які коштуватимуть часу, якщо їх не знати

- **`bun run build` знищує магічні предмети** — використовуй `bunx next build`.
- **`scripts/generate-creatures.ts` — заряджена міна:** пише в той самий шлях, що
  `build-creatures-2014.ts`, віддає 7 записів замість 669, при збої підключення пише **порожній
  масив**. Від запуску його рятує лише те, що він не підвʼязаний до npm-скрипта. Для бестіарію
  2014 використовувати **тільки** `scripts/build-creatures-2014.ts`.
- **`scan-batch.ts` не запускається через `npx tsx`** — top-level `await` плюс відсутній
  `"type": "module"` женуть esbuild у CJS. Конвеєр кличе його через `bun`. З усіх скриптів
  `scripts/aidedd/` це стосується рівно одного.
- **Тести з базою — тільки `bun run test:integration`**, ніколи голим `vitest`: npm-скрипти
  обгортають машинний лок на `spells_test`.
