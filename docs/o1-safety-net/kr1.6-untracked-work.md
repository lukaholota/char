# KR1.6 — Робота повертається в git, CI знову щось означає

**Ціль:** [O1](../README.md#статус) · **Статус:** ⏳ відкладено до релізу · **Залежить від:** нічого

## Коли це робити

**Рішення власника, 2026-08-21: до повного релізу за це не переживаємо.** KR лишається
відкритим, але не є поточною роботою — його треба закрити **перед релізом**, бо саме тоді
відсутність коду в репозиторії стає реальною, а не теоретичною проблемою.

## Мета

Останній коміт — `6a96cdb` від **2026-08-16**. Відтоді накопичилося **476 незакомічених файлів**
і 50 змінених, серед них цілі Objective O7–O13, увесь конвеєр aidedd, довідник правил, шар доступу
до бестіарію й обидва JSON з істотами. Це не `.gitignore` — `git check-ignore` на цих шляхах
мовчить. Їх просто не додавали.

Наслідок, який робить це питанням сітки безпеки, а не охайності: **CI зеленіє на тому, чого в
репозиторії немає.** Збірка з чистого клону падає на `tsc`, бо `bestiaryData.ts` імпортує
`creatures.json`, якого немає ні в git, ні серед восьми файлів, що робить `generate:content`.
Тобто гейт, заради якого існує O1, зараз перевіряє не той код, який задеплоїться.

Друга половина — те, що поза git лежить нерівномірно. Текст 472 магічних предметів урятований
випадково: `prisma/seed/magicItemSeed.ts` відстежується й містить рівно ті самі 472 записи
(звірено за `engName`, 0 розбіжностей). А от `data/aidedd/lists/*.json` і
`scripts/build-magic-items-2014.ts` не відстежуються, попри коментар у `.gitignore`, який каже,
що переліки лишаються в git як вхід для рев'ю.

## Узгоджений scope

1. **Занести в git те, що має там бути:** `scripts/aidedd/`, `data/aidedd/{import-manifest.json,
   lists,terms-registry.md,translations,questions.md}`, `src/lib/generated/creatures.json` і
   `creatures2024.json`, `src/lib/rulesData.ts`, `src/app/rules/`, `src/app/2024/rules/`,
   `src/components/rules/`, шари доступу каталогів, `tests/content/bestiary-*.test.ts`, доки
   O7–O14. Орієнтовно ~6,5 МБ.
2. **Рішення по `data/aidedd/raw/`** — 10 МБ, 1 455 сторінок, зараз у `.gitignore`, і
   `build-creatures-2014.ts` читає його на збірці. Або комітимо, або визнаємо, що каталог істот
   не перезбирається ніде, крім одного ноутбука, і тоді джерелом істини стає згенерований JSON.
3. **Гард у Dockerfile** розширити на істот, щоб збірка падала з текстом, а не десь усередині
   Next. Вісім каталогів там уже перелічені після
   [KR13.6](../o13-2024-completeness/kr13.6-catalog-generators.md).
4. **Перевірити на чистому клоні**, що `bun i && bun run generate:content && bunx tsc --noEmit &&
   bun run test` проходить. Зараз це припущення з читання `deploy.yml`, а не факт.
5. **Розбити на осмислені коміти** за Objective, а не одним «wip». Історія цього репозиторію —
   єдине, що пояснює, чому щось зроблено саме так.

## Поза межами

- Пуш у `main` і деплой. Це окреме рішення власника: у `main` зараз немає ні нових каталогів, ні
  бестіарію, і перший пуш зачепить [ризик №2](../STATE.md) з магічними предметами.
- Прибирання `tmp/` і решти сміття в корені.

## Готово, коли

- [ ] По `data/aidedd/raw/` є записане рішення, а не мовчазний `.gitignore`.
- [ ] Чистий клон збирається й проходить тести — перевірено реально, у тимчасовій теці.
- [ ] Гард у Dockerfile покриває істот.
