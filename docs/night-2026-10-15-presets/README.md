## Рішення планувальника

- **Два шари доказу.** Повний обхід із базою — у `test:integration` (так вимагає мета і так дозволяє
  Р32). У CI йде шар без бази: той самий запит UI, клієнтські перевірки й план на закомічених
  каталогах для кожного пресета й рівня. Повернення бази в CI — рішення власника (скасування Р32).
- **Редакція пресета — це `recipe.ruleset`**, не імʼя файлу. Обхід групує випадки за редакцією,
  бере вміст і очікування цієї редакції й перевіряє, що жоден повʼязаний рядок не з іншої. Для
  редакції без пресетів — один явний пропуск, тож пресети 2024 з `night/presets2024` підключаються
  самими даними.
- **Відомі збої в обході — `it.fails` з ідентифікатором бага.** Набір лишається зеленим для інших
  потоків, а виправлення перевертає тест і змушує зробити його звичайним. Виправлення — раунд 2.
- **Основний клас пресета** — клас із найбільшою кількістю рівнів на найвищому рівні пресета; за
  рівності — стартовий. Ним групують галерея, пошук і заголовок сторінки пресета. Підказка в
  конструкторі й далі зіставляє за стартовим класом: вона пропонує персонажа 1-го рівня, а вимір
  тижня 2 не можна зсувати.
- **Аналітика воронки:** назви й властивості подій не змінюємо, щоб тиждень 2 (19–26.10)
  порівнювався з тижнем 1.
- **Спільне дерево, чотири виконавці.** Коміт лише своїх шляхів: `git commit -m … -- <шляхи>`;
  ніколи `git add -A`. Помилки `tsc`/тестів у чужих файлах не правимо — записуємо. Один dev-сервер
  на дерево: перед стартом `mkdir …/scratchpad/presets/devserver-lock` з task id і PID, порт 3101,
  зупинка за PID, лок прибрати; лок старший за 40 хв — застарілий.
