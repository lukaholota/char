# KR44.3 — Структуроване читання класів і рас

**Ціль:** [O44](README.md) · **Статус:** ✅ 2026-09-26 · **Залежить від:** KR44.2.

## Реалізація

1. Використати наявні `ContentListPage`, Dialog, засоби розділів / вкладок, описів і акцентів.
   Пошукати готові компоненти перед створенням нових. Каталожні дані й дані модалок
   конструктора мають різні типи; не виправляти це `as any` або імпортом creator JSON.
2. Відділити огляд, здібності й перелік гілок. Рендерити потрібне представлення; назви
   здібностей лишаються видимими, опис розгортається незалежно. Додати читання всіх описів.
   Рівень — один семантичний заголовок групи, без повторюваних бейджів у рядках здібностей.
   Назви здібностей — окремий рівень заголовків; наявні іменовані підпункти довгих описів
   мають власні блоки й підзаголовки. Перевірити чинний `FormattedDescription` перед
   вибором реалізації; не переносити спрощений парсер макета в production.
3. Один спільний механізм відкриття гілки для класів і рас із відповідними підписами.
   Не копіювати розмітку для поточних і старих підкласів.
4. На телефоні змінювати вміст відкритого читального Dialog; на десктопі гілка відкриває
   читальний Dialog над деталлю. Повернення відновлює попередній розділ, фокус і скрол.
5. Для класів 2024 зберегти групу «Зі старих книг», назву книги, пояснення і правильні рівні.
6. Контролер цілі послідовно вибирає батька → розділ → гілку → розгортає здібність → чекає
   готовий видимий контейнер → скролить і фокусує. Випадковий timeout не є синхронізацією.

## Готово, коли

- [ ] перший екран огляду не містить повні описи всіх підкласів / підрас;
- [ ] довгі назви карток читабельні на 375 px, цілі натискання достатні для дотику;
- [ ] здібності згруповані за рівнями, можна читати кілька або всі описи;
- [ ] рівень має один заголовок на групу; повторюваних бейджів «1 рів.» немає;
- [ ] назви здібностей помітніші за основний текст; між здібностями щонайменше 24–32 px,
      між групами рівнів 36–40 px (перевірити масштабування й мобільну щільність);
- [ ] довгі описи зберігають абзаци, списки й наявні підпункти; заголовок підпункту
      стоїть над його текстом із виразним відступом;
- [ ] текстова колонка обмежена приблизно 65–70 знаками, шрифти проєкту збережені;
- [ ] ієрархія заголовків змістовна й послідовна, не лише CSS на довільних span;
- [ ] відсутні гілки не створюють порожнього розділу;
- [ ] у відкритого підкласу / підраси видно батька, повернення й закриття;
- [ ] збережені проза, метадані, джерела, режим без ШІ й посилання в описах;
- [ ] статична підсвітка цілі видима на `.glass-card` через outline, без нових анімацій;
- [ ] немає кількох одночасних читальних модалок для класу → підкласу;
- [ ] взаємодія з модалками заклинань / правил з опису перевірена окремо;
- [ ] clean-code-guard застосований після production-правок; потрібні гейти пройдені.

## Журнал

- **2026-09-26** — запропоновано одну модель читання; макет демонструє вигляд, але не
  заміняє браузерних критеріїв KR44.5.
- **2026-09-26, уточнення власника** — додано вимоги до візуального розділення за скриншотом
  здібностей Варвара 2024: заголовки рівнів замість бейджів, більші назви, відступи й
  окремі підзаголовки довгих описів. Це пряма вимога власника, не відкрите питання дизайну.
- **2026-09-26** — розділи на Radix Tabs, `ReadingEntryList`, `BranchCardGrid`, `BranchReader`,
  `CatalogReadingDialog` у `src/components/catalogs/reading/`. Історія: гілка — один запис
  (`reading-history.ts`, стан Next копіюється), Dialog гілки без власного back-hook; хрестик
  мобільної модалки з гілкою знімає обидва записи через `waitForPendingHistoryBack`.
  `replaceUrlSearchParams` більше не стирає `history.state`. `SectionJumpNav` видалено — його
  замінила адресація. Тести `tests/components/catalog-reading.test.tsx`, кожен бачений червоним.
  Chromium 1440 і iPhone 13: переповнення немає, помилок JS немає. Знайдено й виправлено:
  `tailwind-merge` викидав `outline` поруч з `outline-2` — контур цілі був `none`.
