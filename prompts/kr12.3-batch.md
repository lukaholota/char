## Крок 1 — брифінг

```
bun run scripts/aidedd/scan-batch.ts --verify-empty
```

Читає кешовані сторінки, ходить у мережу лише щоб перевірити порожні статблоки на живому сайті,
пише один файл у `data/aidedd/briefings/`. Далі працюй **з брифінгу**, не збирай ці дані наново:

- `isStatblockEmpty` + `liveCheck` — дефект джерела «гола назва дії». Такі істоти **відкладаються**,
  текст їм не вигадується.
- `blockingGaps` — блокування поза дефектом джерела (невідоме джерело, невідомий термін словника).
- `fieldGaps` — поля, для яких потрібен `fields`-обхід у batch-файлі, з англійським оригіналом
  і причиною.
- `featureNames` — для кожної назви риси чи дії: `ratified` (ратифікований словником переклад —
  бери його дослівно, не зважуй варіанти), `canonicalSuffix` (обмеження за використання,
  відрендерене правилом) і `known` (частоти, лише як довідка, коли `ratified` порожній).
- `spellListGaps` — списки заклинань, які парсер губить, з готовими українськими назвами.
- `nameCandidates` — уже ухвалені українські назви цієї істоти або її родини.

Якщо сканер каже «Усі партії RULES_2014 вже розібрані» — це не помилка й не привід спинятись.
Незаймана партія скінчилась, але відкладене нікуди не поділось: партії одноразові, і рядок,
відкладений своєю партією, назад у неї не повертається, навіть коли причина відпала. Тоді бери
добірку — віртуальну партію з усього, що ще `pending`, але має непорожній статблок:

```
bun run scripts/aidedd/scan-batch.ts --gleaning
```

Далі все так само, тільки переклад пиши в `data/aidedd/translations/monsters-2014/gleaning-N.json`
(наступний вільний номер), а `describe`-блок у тесті назви «добірка N», а не «партія N».

## Крок 2 — переклад

Виклич скіл `dnd-ua-translation` **інструментом Skill** (не читай його SKILL.md як файл), далі
напиши `data/aidedd/translations/monsters-2014/batch-NN.json` за форматом попередніх партій.

Правила, які не обговорюються:

- **Якщо `ratified` заповнений — бери його дослівно.** Це `dictionary.json → statblockFeatures`,
  119 ратифікованих назв. Якщо порожній — склади нову назву й далі тримайся її.
- **Обмеження за використання бери з `canonicalSuffix`**, не вигадуй свій формат:
  «(перезарядка 5–6)», «(3 рази на день)», «(перезаряджається після короткого чи тривалого
  відпочинку)».
- **Словник б'є прецедент і частоту.** Якщо назва є контрольованим терміном у
  `src/lib/refs/translation.ts` чи `dictionary.json` (зброя, обладунок, стан, мова, тип ушкоджень),
  бери словниковий варіант, навіть якщо партії писали інакше. Прецедент — `Scimitar` → «Шабля».
- **Списки заклинань** зі `spellListGaps` дописуй у текст запису у форматі «Назва [EngName]»,
  точно як його подає брифінг.
- **Українську назву істоти** бери з `nameCandidates`, якщо там є успадкований запис. Нову складай
  з уже затвердженого й поясни в журналі.
- Опис (`description`) перекладай, коли джерело його має.

## Крок 3 — гейти термінів: НЕ ПИТАТИ, А ВІДКЛАСТИ

Це головна відмінність від ручних сесій. Сесія автономна, відповісти нікому.

- Потрібен **новий термін контрольованого словника** (світогляд, тип істоти, тег типу, мова,

  orc, gnoll, kobold, kuo-toa, dwarf, thri-kreen, yuan-ti). Поясни в журналі.

## Крок 4 — перезбір і тест

```
bun run scripts/aidedd/build-import-manifest.ts
bun run scripts/build-creatures-2014.ts
```

Додай `describe`-блок партії в **той самий** файл `tests/content/bestiary-2014-import.test.ts`
за зразком партії 11: константи `BATCH_<N>_DEFERRED_SLUGS` і `BATCH_<N>_BLOCKED_SLUGS` (порожню
множину лишай явною, з перевіркою `size === 0`), рядок у блоці маніфесту, перевірки на кожен
`fields`-обхід і кожен дописаний список заклинань.

**Доведи, що тест кусається:** зроби копію файлу, зламай одну цільову перевірку, переконайся, що
червоно, відкоти з копії, переконайся, що знову зелено. Якщо якийсь `fields`-обхід тримає саму
збірку каталогу — падіння збірки теж рахується як доказ, воно сильніше.
