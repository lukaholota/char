# Переклад D&D 5e українською

## Джерело істини

`dictionary.json` і `translation.ts` — авторитетні. Якщо термін уже є там, дублюючий термін
під новою назвою не вводиться, і будь-яке правило нижче, що суперечить `dictionary.json`,
програє йому.

**Перед перекладом нового шматка контенту:** знайти в `dictionary.json`, чи термін уже
використовується. `rg -i "<термін>" src/lib/refs/dictionary.json`.

Словник має три верхні ключі, і шукати треба в усіх трьох: `DND_DICTIONARY` (глосарій понять),
`SPELLS` (501 ратифікована назва заклинання) і `CONTENT_TRANSLATIONS` (33 мапи за enum-ключами —
раси, класи, підкласи, передісторії, риси, зброя, обладунки, інструменти, мови, **джерела**;
918 термінів, дзеркало `translation.ts`). Саме на третьому ключі раніше ламалися сесії: назва
«Monster Manual» лежала в `translation.ts` як `MM: "Бестіарій (2014)"`, і той, хто дивився лише
в `DND_DICTIONARY`, вирішував, що терміна немає, — і вигадував свій. **Не знайшов — перевір, чи
ти дивився в усі три ключі, перш ніж казати «терміна немає».**

**Якщо термін новий і в словнику його немає:** зупинитись і запитати власника, як його
записати, перш ніж перекладати далі цим терміном. Не вигадувати переклад мовчки й не
продовжувати з power based-здогадкою — один непогоджений термін, що розповзся по сотнях
рядків content-seed, дорожче виправити, ніж один раз запитати.

## Основні настанови

- Звертання до гравця — на "ви".
- Proficiency: "Ви володієте" / "маєте Володіння". `Proficiency Bonus` — «Бонус Майстерності».
- Стійкі відповідники (звіряти з `dictionary.json`, це не вичерпний список і не заміна йому):
  - "as a bonus action" — бонусною дією
  - "as an action" — дією
  - "as a reaction" — реакцією
  - Dash — Ривок
  - Disengage — Відступ
  - Hide — Сховатися
  - spell slots — слоти заклинань
  - cantrip — замовляння
  - spell known / prepared — заклинання, які ви знаєте / заклинання, які ви підготували
  - Infusion — Вливання
- Числові значення — через "+": "+2", "+2к6".
- Обмеження за використання: "3 per day" → "3 рази на день".
- Не змішувати українську й англійську всередині одного терміна (виняток — формат назв
  заклинань нижче). Якщо термін новий і незрозумілий без оригіналу — короткий переклад у
  дужках: «Величезний (Huge, 15×15 ф.)».
- Імена гравців, NPC, брендів не перекладаються, якщо немає explicit запису в словнику.
- Сучасна українська мова, офіційна стилістика Wizards of the Coast, ігровий жаргон
  прийнятний.

## Форматування довгих описів

- Абзаци розділяти `\n\n` — так само, як на джерельних сайтах.
- `shortDescription` — максимум два речення, українською. Англійська — лише коли потрібен
  однозначний відповідник, якого без оригіналу не впізнати.
- `description` — розгорнутий переклад, стиль офіційних українських книжок D&D, максимально
  близько до оригіналу за змістом і структурою (не переказ, а переклад).

## Назви заклинань усередині описів фіч

Коли опис фічі (раси, класу, риси тощо) згадує конкретне заклинання:

- Вказувати українську назву з англійською в дужках: «Магічний дротик [Magic Missile]».
  Українську назву брати з наявного запису заклинання, не вигадувати нову.
- Для машинного зв'язку з системою заклинань — `givesSpells` з `eng_name` зі списку
  затверджених заклинань, наприклад:

  ```json
  "givesSpells": [
    { "spell_id": 1352, "eng_name": "Mage Hand", "name": "Магічна рука [Mage Hand]" }
  ]
  ```

## Приклад перекладеної фічі класу

```json
{
  "name": "Магічне налаштування",
  "engName": "Magical Tinkering",
  "shortDescription": "Ви можете наділити невелику річ одним з простих магічних ефектів.",
  "description": "Починаючи з 1 рівня, ви опановуєте мистецтво Магічного Налаштування. Ви здатні вкладати базові магічні ефекти у невеликі предмети, як-от створення світла або звуку. Ці налаштування обмежені і не завдають шкоди.",
  "displayType": ["ACTIVE"]
}
```

## Специфіка редакції (2014 проти 2024)

Дотримуватись цих же правил незалежно від `ruleset`. Єдина відмінність — дискримінатор
`ruleset` на рядку контенту й, за потреби для заклинань, на його редакційно-специфічній
накладці; сам стиль перекладу, тон і структура словника — спільні. Не створювати паралельний
словник під 2024: нові терміни йдуть у той самий `dictionary.json` тим самим процесом
узгодження вище.
